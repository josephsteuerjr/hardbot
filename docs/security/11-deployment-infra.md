# 17. Развёртывание и инфраструктура

> Операционный раздел для ИТ/ИБ. **Актуальный способ установки — `deploy/`:**
> Linux-сервер компании с Docker Compose v2, два базовых контейнера
> (`vyezdy-app` — приложение, admin API и необязательный Telegram-бот;
> `vyezdy-stt` — распознавание речи на Unix-сокете) и необязательные профили
> `routing` (OSRM) и `proxy` (Caddy с автоматическим TLS). Пошаговая инструкция,
> требования к памяти, резервные копии и диагностика — в
> [`deploy/README.md`](../../deploy/README.md); установка проверена на сервере
> 02.09.2026 (раздел «Проверено» там же).
>
> Ниже — исторический вариант «Windows + Docker Desktop в филиале ЦА»,
> рассматривавшийся летом 2026. Он остаётся допустимой альтернативой хоста,
> но стек контейнеров и правила доступа берутся из актуального `deploy/`.

## 17.а. Актуальный стек (сентябрь 2026)

| Сервис | Образ | Роль | Сеть | ПД |
|---|---|---|---|---|
| **app** | `vyezdy-app` (сборка из `server/`) | приложение сотрудника (PWA), admin API, бот при заданном `BOT_TOKEN` | `127.0.0.1:${APP_PORT:-8080}`; наружу через обратный прокси с TLS | **Да** |
| **stt** | `vyezdy-stt` (сборка из `stt/`) | распознавание голосовых комментариев (faster-whisper) | без TCP-порта: Unix-сокет в общем томе, токен в `secrets/stt.token` | аудио транзитом |
| **osrm-uz / osrm-tj** *(профиль `routing`)* | `project-osrm/osrm-backend` | порядок объезда по дорогам | только внутренняя сеть compose | нет |
| **caddy** *(профиль `proxy`)* | `caddy:2` | TLS-терминация, если у ИТ нет своего прокси | :80/:443 | транзит |

Данные: `deploy/data/` (SQLite `hardbot.db`, фото, выгрузки) и `deploy/models/`
(кэш моделей речи). Секреты: `deploy/.env` (`ADMIN_API_KEY`, при желании `BOT_TOKEN`)
и `deploy/secrets/stt.token` — создаются `install.sh`, в систему контроля версий не
попадают. Память: app ≈ 0,3 ГБ в работе, stt ≈ 0,7 ГБ (модель `small`, пик ≈ 0,9 ГБ),
`medium` ≈ 1,8 ГБ, `large-v3` ≈ 3,5 ГБ.

# 17.б. Исторический вариант: Windows + Docker Desktop

> Операционный раздел для ИТ/ИБ: **как система разворачивается, эксплуатируется, обновляется
> и как до неё безопасно достучаться.** Концептуальная архитектура и зоны доверия —
> [01-architecture.md](01-architecture.md) и [02-data-flows-dfd.md](02-data-flows-dfd.md);
> здесь — конкретный стек и эксплуатация.

## 17.0. Исходные условия (зафиксировано с владельцем)

- **Почему Центральная Азия.** Система завязана на Telegram (бот + Mini App), а в РФ Telegram
  **под запретом — разворачивать его там значит нарушать закон**. У компании есть **филиал в ЦА**,
  где Telegram доступен штатно, — там контур и работает.
- **Чьи данные и где.** Обрабатываются ПД **должников и сотрудников с гражданством ЦА** → их
  резидентность естественно ложится на ЦА. Плюс жёсткая политика компании: **ПД не хранятся в
  «недружественных» юрисдикциях** (никаких западных облаков/CDN). Вся инфраструктура —
  **компании** (ПК филиала, ВПС, хранилище бэкапов) и в дружественной юрисдикции.
- **Хост.** Обычный **мощный ПК под Windows** с **Docker Desktop** (бэкенд WSL2) в филиале ЦА.
  Отдельный Linux-сервер не нужен. Тяжёлые сервисы (OSRM/VROOM) — Linux-only, поэтому идут
  **Linux-контейнерами внутри Docker Desktop** на этой же машине.
- **Правовой маппинг** (ZRU-547 для УЗ; закон № 1537 для ТДж; 152-ФЗ — если попадают данные
  граждан РФ) — в [09-legal-mapping.md](09-legal-mapping.md).

## 17.1. Решение: Docker Desktop (Windows) + Compose — и почему так для ревью

- **Декларативность** — весь стек описан в `compose.yml`; читается и заверяется как код.
- **Воспроизводимость** — `docker compose up -d` поднимает одинаковый стенд на любой машине.
- **Версии под контролем** — образы пиннятся по тегу (не `latest`) → управляемость уязвимостей.
- **Простой откат** — предыдущий тег образа + git-тег кода (`known-good-*`).
- **Windows-хост** — это «обычный мощный ПК», без отдельного сервера; at-rest шифрование —
  BitLocker (реестр go-live п.2). Docker Desktop настраивается на автозапуск при входе/загрузке.

> Бот и движок — Python, могут идти и **нативно на Windows**; в Docker их кладём ради
> единообразия запуска и изоляции. OSRM/VROOM — **только** в контейнерах (Linux).

## 17.2. Состав стека (контейнеры в Docker Desktop)

| Сервис | Образ (пин по тегу) | Роль | Доступ/порт | ПД |
|---|---|---|---|---|
| **caddy** | `caddy:2` | Реверс-прокси + TLS | **единственный публичный вход** | транзит (TLS) |
| **bot** | свой `hardbot:x.y` | Бот (aiogram polling) + миниапп (aiohttp) | за Caddy; исходящий polling к Telegram | **Да** |
| **engine** | свой `kontur-engine:x.y` | FastAPI: дашборд/аналитика/маршрут | `127.0.0.1:8090`, токен `ENGINE_API_TOKEN` | только при `HARDBOT_DB` |
| **osrm** | `ghcr.io/project-osrm/osrm-backend:<пин>` | Матрица/геометрия по дорогам | `127.0.0.1:5001` + сеть `kontur-net` | Нет |
| **vroom** | `vroomvrp/vroom-docker:v1.x` | VRP — порядок объезда/бригада | `127.0.0.1:3000` + `kontur-net` | Нет |
| **backup** | `borgmatic` (sidecar) | Шифрованный бэкап БД + ротация | нет портов | Да (шифр.) |
| **postgres+postgis** *(план, профиль `full`)* | `postgres:16` | Геозапросы/кластеры/мультифилиал | `127.0.0.1:5432` | Да |

> Данные на томах Docker (`hardbot.db`, граф OSRM, PMTiles). Пульт (Qt) в образ не входит:
> это настольная программа. Карты PMTiles раздаёт Caddy (Range).

## 17.3. Сеть и сегментация

- Одна внутренняя docker-сеть `kontur-net`; сервисы общаются **по именам** (`osrm-tj:5000`) —
  внутренние IP контейнеров динамические, но скрыты DNS и роли не играют.
- **Наружу смотрит только Caddy.** Движок, OSRM, VROOM, БД — слушают **только `127.0.0.1`**
  (на Windows — проброс Docker Desktop на loopback хоста).
- Брандмауэр Windows — default-deny на вход; единственный вход — контролируемый канал миниаппа (17.4).
- `restart: unless-stopped` + автозапуск Docker Desktop — стек поднимается после перезагрузки ПК.

## 17.4. Доступ и проблема «адрес меняется после перезагрузки» — решение

Это вопрос **слоя доступа**, а не ОС/Docker. Три канала, ни одному не нужен статический IP:

1. **Бот ↔ Telegram — исходящий long polling.** Машина стоит в регионе, где **Telegram доступен**
   (Центр. Азия), поэтому бот просто звонит наружу. Входящий статический IP **не нужен** →
   смена IP после ребута бота не ломает; вебхук-порт наружу не открывается.
   *(Если какой-либо узел окажется в сети, где Telegram режется DPI, — связь поднимается через
   DPI-устойчивый туннель AmneziaWG; в штатной УЗ/ТДж-конфигурации это не требуется.)*
2. **Миниапп — нужен стабильный публичный HTTPS-URL** (Telegram открывает его на телефоне выездника).
   Даётся **реверсом через ВПС компании** в дружественной юрисдикции: ПК филиала держит исходящее
   соединение к этому ВПС, ВПС отдаёт стабильный домен. **TLS терминируется на инфраструктуре
   компании** — трафик с ПД не проходит через сторонние/западные CDN. URL стабилен независимо от
   того, как скачет IP филиала.
3. **Админ-доступ к ПК — Tailscale / Headscale.** Постоянный адрес **поверх любого меняющегося IP**,
   работает за CGNAT и за корпоративным VPN; RDP/SSH — только через оверлей, публичный порт закрыт.
   Headscale (свой контрол-сервер) — план Б при блокировке координационного домена Tailscale.

**Итог:** на ПК нет ни одного проброшенного наружу порта, кроме контролируемого канала миниаппа.
Динамический IP, NAT и корпоративный VPN перестают быть проблемой — без статического IP.

## 17.5. Данные, резидентность, бэкапы

- ПД хранятся **только локально** на этом ПК, в стране размещения (см. §03, §09).
- **Бэкап:** `borgmatic` (дедуп + шифрование) локально, плюс `rclone`-копия в **объектное хранилище
  компании в дружественной юрисдикции** (резидентность бэкапов; не в «недружественных» странах).
  Ротация `keep_daily: 7, keep_weekly: 4`. Восстановление проверяется `selftest` (см. §07).
- Деплой/бэкап не выносят `.env`/`*.db` за периметр (`.dockerignore` + правила деплоя).

## 17.6. Обновления, патчинг, откат

Образы пиннятся (ISO A.8.8). Обновление: новый тег → `docker compose pull && up -d`. Откат:
предыдущий тег + git-тег кода. Регулярный пересбор базовых образов (патчи ОС/библиотек) и
обновление самого Docker Desktop / Windows.

## 17.7. Хардненинг

Версии пиннятся (не `latest`) · секреты через `env_file`/Docker secrets, вне образа ·
минимальные базовые образы · внутренние порты только на `127.0.0.1` · `restart: unless-stopped` ·
healthcheck (`/healthz`) · BitLocker на диске ПК (at-rest) · ограниченная учётка Windows для сервиса.

## 17.8. Железо (ориентир)

Обычный мощный ПК: 8+ ядер, **32 ГБ ОЗУ**, 500 ГБ NVMe, Windows 10/11 Pro (нужен Hyper-V/WSL2
для Docker Desktop), опц. ИБП. На 32 ГБ комфортно живёт весь гео-стек Средней Азии
(PMTiles + OSRM + VROOM (+ PostGIS)). Отдельный сервер покупать не требуется.

## 17.9. Маппинг на контроли и закон

| Контроль / требование | Как закрыто инфраструктурой |
|---|---|
| Локализация ПД (УЗ ZRU-547 ст.27-1; ТДж № 1537; 152-ФЗ — если есть данные граждан РФ) | Хранение и бэкапы — инфраструктура компании в ЦА (дружественная юрисдикция), не в «недружественных» странах; данные не покидают периметр |
| Сегментация сети (ISO A.8.22) | Одна docker-сеть; всё внутреннее на `127.0.0.1`; наружу только Caddy |
| Резервное копирование/восстановление (A.8.13) | borgmatic + rclone (в юрисдикции), проверяемый restore |
| Управление уязвимостями (A.8.8) | Пиннинг образов + регулярный пересбор; апдейт Docker Desktop/Windows |
| Контроль доступа администратора (A.5.15 / A.8.5) | Tailscale/Headscale + ключ; MFA — реестр go-live п.6 ([10](10-go-live-register.md)) |
| Защита носителя at-rest | BitLocker на диске ПК — реестр go-live п.2 |

## Приложение A. Скелет `compose.yml` (иллюстративно; работает и в Docker Desktop на Windows)

```yaml
# Иллюстрация принципа, не итоговый прод-файл. Версии — пиннить.
services:
  caddy:                      # единственный публичный вход (TLS)
    image: caddy:2
    restart: unless-stopped
    ports: ["443:443"]
    volumes: [ ./Caddyfile:/etc/caddy/Caddyfile, caddy_data:/data ]
    networks: [ kontur-net ]

  bot:                        # бот + миниапп; исходящий polling к Telegram
    image: registry.internal/hardbot:1.x
    restart: unless-stopped
    env_file: .env            # секреты вне образа
    volumes: [ pd_data:/data ]   # SQLite hardbot.db — том
    networks: [ kontur-net ]

  engine:                     # FastAPI — только loopback, под токеном
    image: registry.internal/kontur-engine:1.x
    restart: unless-stopped
    environment: [ "ENGINE_API_TOKEN=${ENGINE_API_TOKEN}", "OSRM_URL=http://osrm:5000", "VROOM_URL=http://vroom:3000" ]
    ports: ["127.0.0.1:8090:8090"]
    networks: [ kontur-net ]

  osrm:
    image: ghcr.io/project-osrm/osrm-backend:<pin>
    restart: unless-stopped
    command: osrm-routed --algorithm mld /data/region.osrm
    volumes: [ ./osrm:/data ]
    networks: [ kontur-net ]   # наружу не публикуется

  vroom:
    image: vroomvrp/vroom-docker:v1.x
    restart: unless-stopped
    networks: [ kontur-net ]

  backup:                     # borgmatic → rclone в хранилище компании (дружественная юрисдикция)
    image: ghcr.io/borgmatic-collective/borgmatic:<pin>
    restart: unless-stopped
    volumes: [ pd_data:/data:ro, ./borg:/repo ]

volumes: { pd_data: {}, caddy_data: {} }
networks: { kontur-net: {} }
```

> Доступ к ПК (Tailscale/Headscale) и публичный URL миниаппа (реверс через ВПС компании) —
> на уровне хоста Windows, вне этого compose.
