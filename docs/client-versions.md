# Версии клиентов по устройствам

Сервер сохраняет наблюдения в `account_client_versions`: аккаунт, логическое
устройство, внутренняя сессия, `client_version`, `shell_version`, `product`,
`source`, первое/последнее наблюдение и `login_at` для успешного входа.
Время записывается в UTC. Сырые токены и User-Agent не сохраняются.

Запись начинается с установки этого серверного изменения. Устройства с уже
открытой сессией учитываются при следующем API-запросе; повторный вход не нужен.
Историю до установки сервер не восстанавливает предположениями.

Источники версии:

- `desktop`: заголовок `X-Client-Version` от Electron-клиента; текущие настольные
  продукты передают `app.getVersion()` и `X-Work-Product`. Начиная с Analyst3.2.8,
  Python-мост получает эту версию от приложения и передаёт `X-Client-Runtime:
  desktop` вместе с продуктом `analyst`.
- `pwa`: известна версия мобильной/браузерной оболочки `X-Shell-Version`.
  Её `X-Client-Version: 3.2.0` обозначает совместимость протокола, а не версию
  установленного настольного приложения.
- `compatibility`: запрос старого Python-моста, чей заголовок версии обозначает
  совместимость. Он не подменяет установленную версию в сводке устройства.
- `reported`: версия из заголовка, когда тип клиента точно не определён.

Заголовки являются диагностикой клиента, а не доказательством подлинности
бинарного файла. Они не меняют права или правила допуска.

Для каждой комбинации сессии, версии, продукта и источника сохраняется отдельная
строка. Первое наблюдение и смена версии записываются сразу. Повторные запросы
той же версии обновляют `last_seen_at` не чаще раза в минуту. Отсутствующие или
некорректные заголовки не заменяют ранее известные значения выдуманной версией.
Неизвестные, отозванные токены и закрытые аккаунты не создают наблюдений;
действительные сессии в ожидании подтверждения учитываются без открытия доступа.

`GET /admin/accounts.json` сохраняет прежние поля и добавляет каждому устройству
`client` (последнее наблюдение, кроме Python compatibility) и `client_versions`
(до 20 последних наблюдений). Полная история остаётся в БД. Внутренние номера
сессий в этот ответ не включаются. При удалении аккаунта его наблюдения удаляются
в той же транзакции.

Пример чтения полной истории:

```sql
SELECT a.username, d.kind, d.label, v.client_version, v.shell_version,
       v.product, v.source, v.first_seen_at, v.last_seen_at, v.login_at
FROM account_client_versions v
JOIN accounts a ON a.id = v.account_id
JOIN account_devices d ON d.id = v.device_id
ORDER BY v.last_seen_at DESC, v.id DESC;
```
