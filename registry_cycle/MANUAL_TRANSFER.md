# Ручной перенос реестров

## Шаг 1 — вверх

Приложение находит личные `.xlsb`, снимает стабильные локальные копии и
собирает разрешённые поля сотрудника в общий реестр по КД и текущему
ответственному общего реестра. Аналитические платёжные колонки запрещены.

После проверки оператор подтверждает точный digest фразой из
`manual_upward.confirmation_phrase`. Публикуется только общий реестр. Его
предыдущее состояние сохраняется в `manual_upward.backup.directory`, а
квитанция — в `manual_upward.backup.receipt_directory`.

## Шаг 2 — вниз

Шаг всегда начинает новый snapshot и заново читает общий и личные реестры. Он
строит полные личные проекции по `ответственный Сотрудник` общего реестра.
Имена папки и файла не участвуют в распределении.

Порядок столбцов личной книги сохраняется. Сопоставление идёт по названиям и
настроенным алиасам; недостающие профильные столбцы добавляются справа с типом
и форматом общего реестра. Неизвестные именованные столбцы не удаляются молча,
а блокируют шаг. Безымянные столбцы сохраняются по КД только в исходной личной
книге и не переносятся в общий.

Если личные книги содержат хотя бы одно изменение, ещё не перенесённое в общий,
шаг 2 останавливается с требованием сначала повторить шаг 1. Поэтому раздача
никогда не скрывает свежую работу сотрудника.

Публикуются только личные файлы, чья табличная проекция действительно
изменилась. Общий реестр служит read-only guard: его изменение после snapshot
отменяет и откатывает раздачу. Backup каждого личного файла сохраняется по
структуре `manual_downward.backup.layout`; квитанция перечисляет каждый файл,
ответственного, строки, изменённые ячейки и SHA-256 до/после.

## Что считается источником

Схема папок: `корень / группа / сотрудник / ФИО.xlsb`. Все группы под выбранным
корнем участвуют, кроме начинающихся с настроенного архивного префикса. В папке
сотрудника рабочая книга называется по ФИО. Копии, даты и прочие имена рядом
не попадают в перенос и не мешают ему. Если есть только посторонние `.xlsb`,
но нет книги по ФИО, проверка сообщает об отсутствующей рабочей книге.

Ответственный непустой книги должен быть единственным. Полностью пустая книга
без ответственного пропускается: угадывать владельца по названию запрещено.

Старые книги во вложенных городских подгруппах находятся вне этой маски.
Назначения приложения берутся из общего реестра, а не из таких копий. При переходе
Хард → Софт импортировать оба профиля с полным срезом выбранных сотрудников,
включая прежних владельцев из списка БД. Полный срез снимает выбранное назначение
при отсутствии КД или пустой колонке владельца этого профиля; частичный импорт
не снимает Хард по пустой ячейке. Предпросмотр показывает состав снятий до записи.

## Отчёты

Каждая проверка остаётся в `_local/registry_cycle_v2/runs/<run_id>`:

- `snapshot.json` — точные источники и SHA;
- `plan.json` / `plan.txt` — поклеточный план;
- `downward.json` / `downward.txt` — изменения личных проекций;
- `staging/validation.json` — итог проверки;
- `publish.journal.jsonl` — журнал публикации;
- `receipt.json` — локальная копия архивной квитанции.

Ни расписание, ни автоматическая публикация, ни закрытие месяца из этого окна
не запускаются.
