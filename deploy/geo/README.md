# Карты и маршруты — развёртывание

Этот слой отвечает за две вещи в приложении: **порядок объезда по реальным
дорогам** (а не «по прямой») и **карту**, которая рисуется своим тайлсетом, а не
тянется из интернета на каждом экране.

Без него бот работает: порядок объезда считается упрощённо, карта падает на
растровый OpenStreetMap. Но обе фичи из тех, ради которых всё затевалось.

## Главное, что стоит знать заранее

**Гигабайты никуда не везут.** Дорожные графы и тайлы собираются на месте из
открытых источников — Geofabrik (выгрузки OpenStreetMap) и ежедневные сборки
Protomaps. В передаче участвуют только эти пять коротких скриптов. Считайте на
сборку несколько часов машинного времени и порядка 10 ГБ на диске.

**Память.** Собранный граф OSRM отображается в память целиком (mmap). Ставить
контейнеру потолок памяти ниже размера графа — гарантированный OOM: узбекский
граф около 927 МБ, и ровно на этом бот убивало пять раз подряд. Либо не
ограничивать вовсе, либо ставить с запасом.

## Что стоит на боевой машине сейчас

| Страна | Файл графа | Порт | Размер |
|---|---|---|---|
| Таджикистан | `tajikistan.osrm` | 127.0.0.1:5001 | ~230 МБ |
| Узбекистан | `uzbekistan.osrm` | 127.0.0.1:5002 | ~927 МБ |
| Россия | `samara_oblast.osrm` | 127.0.0.1:5003 | ~206 МБ |

Россия — это **только Самарская область**, не вся страна. Для расширения нужен
свой граф на каждый регион (или один большой, но тогда считайте память).

Плюс VROOM на 127.0.0.1:3000 и тайлы `basemap.pmtiles` (~3 ГБ, вырезка
z0–13 по прямоугольнику от Средней Азии до европейской части РФ).

## Порядок развёртывания

1. **`osrm_build.sh`** — по одному прогону на страну. Скачивает выгрузку с
   Geofabrik, прогоняет три стадии подготовки графа и поднимает контейнер.

   Скрипт лежит здесь **ровно в том виде, в каком он отработал на бою**, то есть
   собирает Таджикистан. Для другой страны меняются четыре вещи и ничего больше:
   ссылка на `.osm.pbf`, папка данных, имя контейнера и порт. Намеренно не стал
   делать его «универсальным»: проверенный скрипт дороже красивого.

2. **`vroom_build.sh`** — оптимизатор порядка точек. Ставится один раз на все
   страны.

   В его конфиге прописан OSRM таджикистана — **это не имеет значения и чинить
   не надо**. Бот считает матрицу расстояний сам, по графу нужной страны, и
   передаёт VROOM готовую; собственным маршрутизатором VROOM не пользуется.

3. **`pmtiles.sh`** — вырезает тайлы карты из свежей сборки Protomaps по
   прямоугольнику координат. Готовый `basemap.pmtiles` кладётся в том данных
   бота (`/data/basemap.pmtiles`) — дальше бот раздаёт его сам по `/tiles/`.

4. **`osrm-warm.sh`** — прогрев. Граф читается с диска лениво, поэтому первый
   запрос по «холодному» участку тормозит почти на секунду. Один прогон
   подтягивает граф в кэш, дальше ответы за сотые доли секунды. Имеет смысл
   вешать на запуск машины.

5. **Прописать адреса** в `.env` бота:

   ```
   OSRM_URL_UZ=http://osrm-uz:5000
   OSRM_URL_TJ=http://osrm-tj:5000
   OSRM_URL=http://osrm-ru:5000
   VROOM_URL=http://vroom:3000
   ```

   Пустой `VROOM_URL` — порядок считается локальным алгоритмом. Пустые адреса
   OSRM — расстояния по прямой. Ошибка любого из сервисов не роняет бота: он
   молча падает на упрощённый расчёт.

   Контейнеры маршрутизации и бот должны видеть друг друга по именам, то есть
   стоять в одной docker-сети.

## Чего здесь нет

`setup.sh` и `caddy.sh` относятся к отдельному сервису `kontur-engine` —
надстройке над OSRM и VROOM со своим веб-интерфейсом. **Боту он не нужен:**
маршрутный сайдкар ходит к OSRM и VROOM напрямую, мимо него. Скрипты приложены
для полноты картины боевой машины, разворачивать их не требуется. Исходники
самого движка лежат отдельным архивом на сервере и в этот репозиторий не входят.
