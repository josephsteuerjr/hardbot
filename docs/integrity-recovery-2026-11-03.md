# Повтор операций и подтверждение доставки — 3.2.22

Повтор завершённого выезда проверяется по автору, договору и отпечатку полного
запроса. Новый выезд сохраняет исходные значения и фиксированный набор договоров
в одной транзакции с историей и текущим состоянием. Тот же запрос возвращает
прежний результат; изменённое содержимое с прежним ID получает конфликт.
Серверные вычисления геоконтроля не меняют отпечаток исходного HTTP-запроса.

Исторические выезды без отпечатка не получают выдуманного подтверждения полного
состава: при повторе сервер сообщает, что результат уже сохранён и требуется
сверка. Исходная история и очереди не удаляются. Новые операции действующих
клиентов поддерживаются без изменения протокола формы. Разные ID звонков
обозначают разные события, в том числе при одинаковом тексте в одну секунду.

Квитанции обогащения хранятся отдельно от последних значений ячеек.
`receipt_digest` связан с отпечатком состава, количеством записей и временем
приёма. Повтор подтверждённой квитанции не откатывает более позднюю доставку.
Другой состав с прежним digest отклоняется целиком. GET существующего
`/admin/enrichment/ledger.json?receipt_digest=...` возвращает квитанцию только
после штатной проверки полномочий администратора.

Очередь Аналитика восстанавливает потерянный ответ по точной квитанции либо
по совпадению digest и полных метаданных записи в конкретной книге.
Одинаковый текст другой операции не доказывает доставку. При появлении более
поздней неподтверждённой операции требуется сверка; автоматическая перезапись
книги запрещена. Старые серверы без новых метаданных не дают ложного успеха.

Миграция аддитивная: три nullable-поля `visits` и новая таблица
`enrichment_receipts`. Старые факты не переисполняются. Сначала обновляется
сервер, затем Аналитик. Контракт обмена 11 и PWA 110 сохраняются. При откате
возвращается код на текущих томах; рабочая база не заменяется старой копией.

Проверки: повтор выезда с изменением непоказанного в тексте поля, даты и гео;
два самостоятельных звонка с одинаковым текстом; конфликт digest; повтор
старой квитанции после новой доставки; восстановление после потери ответа;
нативная запись Excel без повторной публикации, включая одинаковые значения
другой квитанции. Синтетические профили и базы отделены от рабочих.
