## Роли

`managers.role` — `'manager'` (по умолчанию) или `'security'` (безопасник).
Охват безопасника — те же поля, что у руководителя (direction tj/uz/all,
офисы, список). Владелец (ADMIN_ID) может всё.

Возможности (`caps`) считает сервер:

| cap | manager | security | owner |
|---|---|---|---|
| `team_links` — выдавать/отзывать вход выездникам | да | нет | да |
| `plan_edit`, `pushes_edit`, `binds_edit` | да | нет | да |
| `control` — раздел «Контроль» (`/api/control/*`) | нет | да | да |
| `activity` — лента активности | да | да | да |

Безопасник на пишущих ручках руководителя получает 403 `{"error":"read_only"}`.
Раздел «Контроль» руководителям не показывается: если руководитель в доле,
флаги нельзя показывать тому, кого они касаются.

## Вход пульта руководителя: ключ → токен устройства

Таблица `manager_devices`: `id`, `telegram_id`, `token_hash` (sha256 hex,
UNIQUE), `device` (имя компьютера ≤80), `created_at`, `last_seen_at`,
`last_ip`, `revoked_at`, `revoked_by`. Срока нет — живёт до отзыва.

1. `POST /api/manager/device/enroll`
   тело `{"code": "<код ссылки входа /i/<code>>", "device": "RBR-PC19 · egor"}`
   → 200 `{"token": "...", "device_id": 7, "me": {...}, "caps": {...}}`.
   Ключ — та же ссылка входа руководителя, что выдаёт аналитик («Руководители»
   → «выдать вход») или руководитель себе; обмен считается одним использованием
   ссылки, как `/api/redeem`. Ошибки: 400 `{"error":"bad_code"}`;
   410 `{"error":"link_used"|"link_expired"|"link_unknown"}`;
   403 `{"error":"not_manager"}`. Промахи режутся тем же ограничителем, что
   `/api/redeem`.
2. Заголовок `X-Pult-Token: <token>` — принимается **только** на
   `/api/manager/*` и `/api/control/*` (портфель выездника им не открыть).
   - живой → uid владельца; `last_seen_at`/`last_ip` пишутся не чаще раза в минуту;
   - отозванный → **строка удаляется**, ответ 401 `{"error":"device_revoked"}`;
   - неизвестный → 401 `{"error":"device_unknown"}`.
   Удаление руководителя (`/admin/manager_delete`) удаляет и его устройства.
3. `GET /api/manager/device/me` → `{"device_id","device","created_at",
   "me":{"name","role","direction","office_cities"},"caps":{...},"server_time"}`.
4. `POST /api/manager/device/logout` → удаляет свою строку, `{"ok":true}`.
5. Аналитик (админ-доступ, `X-Device-Token`/мастер-ключ):
   - `GET /admin/manager_devices.json[?telegram_id=]` →
     `{"devices":[{"id","telegram_id","manager_name","role","device",
     "created_at","last_seen_at","last_ip","revoked_at"}]}`;
   - `POST /admin/manager_device/revoke.json` `{"id":7}` или
     `{"telegram_id":123,"all":true}` → ставит `revoked_at` (строка висит со
     статусом «отозван, ждёт стука», пока устройство не постучится).
   - `/admin/manager` принимает `"role": "manager"|"security"`, а
     `/admin/managers` его отдаёт.

Приложение хранит токен зашифрованным (Electron `safeStorage`, DPAPI) и при
401 `device_revoked`/`device_unknown` стирает токен и все кэши, показывая
экран ключа с объяснением.

## Активность (руководитель и безопасник)

`GET /api/manager/activity?from=&to=&office=&employee=&kinds=&before=&limit=`
(даты `YYYY-MM-DD`, окно по умолчанию — сегодня; `kinds` — через запятую из
`visit,photo,login,flag`; `before` — курсор; `limit` ≤ 500, по умолчанию 200)

```json
{
  "range": {"from":"2026-09-29","to":"2026-09-29","label":"сегодня"},
  "tz": "Asia/Dushanbe",
  "offices": [{"code":"Худжанд","label":"Худжанд","n":6}, {"code":"!none","label":"Без офиса","n":1}],
  "employees": [{"employee":"ФИО","office":"Худжанд","visits":5,"first":"09:12","last":"16:40",
                 "far":1,"late":0,"flags":2,"last_seen":"2026-09-29T16:41:00+05:00"}],
  "events": [{
    "id":"v2081","kind":"visit","at":"2026-09-29T09:14:03+05:00","day":"2026-09-29",
    "employee":"ФИО","office":"Худжанд","rep":"47892257","debtor":"Фамилия И.",
    "title":"Выезд · Обещает оплатить","detail":"1 200 до 05.10",
    "evidence":"at_address|near|far|none","dist_m":35,"fill_s":210,"late_h":0,
    "photos":2,"flags":["far","late","fast_fill","night","cash_words"]
  }],
  "next_before": "cursor-or-null",
  "generated_at": "2026-09-29T16:45:00+05:00"
}
```

`at` — когда событие дошло до сервера, в поясе офиса; `day` — день выезда.
`late_h` — на сколько часов позже конца дня выезда выезд доехал. Охват — как у
остальных ручек руководителя (window_team). Доступ пишется в audit.

## Контроль (только cap `control`)

Смысл: выездник берёт наличные «в счёт долга» и не сдаёт, или пишет выезд,
которого не было. Три слоя: **сигналы** из данных, **контрольный обзвон**
должников, **журнал проверок**.

- `GET /api/control/overview?from=&to=&office=` →
  `{"range","offices","rows":[{"employee","office","visits","risk":0..100,
  "level":"low|mid|high","signals":[{"key","label","value","peer","n"}],
  "checks":{"done","confirmed","no_visit","cash"}}],"legend":[{"key","label","hint"}]}`
  Сигналы (каждый — доля/счёт у человека против медианы его офиса/направления):
  `far_share` далеко от адреса; `no_geo_share` без точки телефона;
  `late_share` занесён позже дня выезда; `fast_fill` карточка заполнена быстрее
  40 с; `night` выезд 21:00–07:00; `speed` соседние выезды с невозможной
  скоростью (>80 км/ч); `cash_words` в тексте выезда «наличные / передал
  деньги / отдал сотруднику» (ru/tj/uz); `paid_no_payment` «оплатил»/обещание,
  а платежа в реестре (`last_payment_date`) после выезда нет, когда срок
  прошёл; `repeat_no_result` ≥3 выездов к должнику без результата;
  `callback_bad` обзвон: «визита не было» / «деньги отдал сотруднику».
- `GET /api/control/flags?employee=&from=&to=` → `{"employee","visits":[событие
  активности + "flags":[{"key","label","detail"}]]}`.
- `GET /api/control/callbacks?date=&office=` → список контрольного обзвона на
  день: `{"date","items":[{"visit_id","employee","office","day","debtor",
  "phones":[..],"address","reported":"что написал выездник","promise":{"sum",
  "date"}|null,"why":"случайная выборка|флаг: …","status":"todo|done",
  "outcome","note","checked_at"}],"script":["…вопросы на ru…"]}`.
  Выборка детерминирована на дату и закрепляется в базе при первом запросе:
  ~10% выездов дня (не меньше одного на сотрудника за неделю) + все выезды с
  сильными флагами.
- `POST /api/control/callback` `{"visit_id":2081,"outcome":"confirmed|no_visit|
  cash_to_employee|paid_elsewhere|no_answer|refused|wrong_number","note":"…"}`
  → `{"ok":true,"check":{…}}`. Таблица `control_checks` (visit_id UNIQUE,
  selected_on, selected_why, checker_uid, outcome, note, checked_at).
- `GET /api/control/export.xlsx?from=&to=` — сигналы и проверки (формулы —
  текстом).

Телефоны и адреса должников безопасник видит — каждое чтение пишется в audit.
