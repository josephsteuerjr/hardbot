# Проверка настольного выпуска

## Раздельное имя портфеля Харда — 27.10.2026

Хард использует явное имя своего портфеля из product_names при загрузке,
чтении карточки, записи и построении маршрута. Переключатель Харда в режиме
Софта проверяет этот же портфель. Имя аккаунта и UID в identity и Hard bootstrap
сохраняются: очередь телефона продолжает узнавать своего владельца.
Версия кэша учитывает обе явные подписи портфелей одного сотрудника.

Повтор офисной записи после настройки имени Харда принимается как дубликат
только при прежнем UID, явно сопоставленном имени и полностью прежнем теле.
Исторический автор и сохранённый факт не переписываются. Офисный отчёт Харда
учитывает прежнее имя автора вместе с настроенным именем его портфеля.

Проверки: test_hard_product_identity, test_pc_first_accounts,
test_office_workspace, test_search_translit — 61 passed. Проверены ПК/телефон,
оба портфеля, отказ по чужому договору, прогрев карточек, реальная функция
владельца очереди PWA и повтор потерянного подтверждения. Серверная поставка
не требует новых установщиков и не изменяет назначения из общего реестра.

## Список регистрации после импорта — 27.10.2026

Новые ответственные из загруженных портфелей появляются в списке выбора себя,
даже когда справочник сотрудников уже заполнен. Проверка заявки использует
тот же список. Люди из справочника без договоров остаются доступными для
выбора. Отключение сотрудника и явные имена его портфелей сохраняют приоритет;
алиасы и подписи Хард/Софт известного человека не предлагаются как второй
человек. Неоднозначные идентичности не добавляются автоматически.

Список читается без записи в БД. Аккаунт и устройство создаются только при
обычной регистрации и требуют прежнего подтверждения руководителем.
Офис берётся только из справочника офисов сотрудника, а не из города должника.
Проверки: `tests/test_staff_registration_candidates.py`,
`tests/test_pc_first_accounts.py`, `tests/test_team_work.py` — 45 passed.
Исправление серверное; новые установщики для него не требуются.

## Аналитик 3.2.13

При выборе файла для импорта включены полный срез для выбранных сотрудников,
возврат ручных снятий и проверенные офисные правки результатов Софта.
Замена комментариев текущего месяца выключена; её можно включить отдельно.
Новый файл восстанавливает эти значения. Смена типа сотрудников сохраняет
полный срез. Предпросмотр и отдельное подтверждение импорта сохранены.

`npm run test:registry-defaults` проверяет настоящий экран: выбор файла,
параметры запроса предпросмотра, включение комментариев вручную, сброс при
новом файле и смену типа сотрудников. Проверка использует синтетический
профиль и не обращается к рабочей базе. Установщик отдельно проходит аудит
содержимого и запуск со встроенным модулем на изолированном профиле.
Хард, Софт и Руководитель остаются версии 3.2.12; их установщики и файлы
обновлений включены в общий выпуск без изменения байтов.

## Состав 3.2.12

Все четыре приложения получают доску сотрудников и задачи в своих областях
доступа. Аналитик также получает исправление ожидания длительных операций.
Хедлесс через настоящий экран обогащения и постоянный Python-журнал
воспроизведены два случая: потеря ответа опроса прекращала ожидание, а
перерисовка экрана скрывала прогресс и завершённый результат при продолжающейся
фоновой задаче. Теперь ожидание восстанавливает чтение того же UUID; старт
операции не повторяется. Текущий экран показывает прогресс и итог после
перерисовки, а действия обогащения блокируются на время работы.

Регрессия: `npm run test:enrichment-ui`. Она проверяет потерю ответа и
перерисовку настоящего renderer с изолированными постоянными задачами.
Отдельный `tools/test-backend-excel.py` проверяет настоящий frozen runtime,
HTTP, Excel/COM и запись синтетической XLSB с сохранением постороннего листа.
Реальные книги для воспроизведения не изменяются. Это исправление ожидания
не отменяет защиту открытых/изменённых книг и проверку квитанции после записи.

## Уточнение 27.10.2026: убрать сотрудника с сохранением аккаунта

На карточке одна кнопка «Убрать». Она открывает вопрос «Удалить также профиль?»
с вариантами «Убрать без удаления», «Убрать и удалить профиль» и «Отмена».
Первым выбран вариант с сохранением аккаунта. Скрытие с доски хранится отдельно
от активности справочника и не меняет пароль, устройства, входы, назначения
или задачи. Вернуть сотрудника можно через добавление из реестра.
Удаление профиля требует явного выбора второго варианта и сохраняет прежние
проверки прав, ID аккаунта и номера операции. Проверены 27 адресных серверных
сценариев, TypeScript/build и Electron-путь с обоими вариантами и отменой.
Изменения остаются локально подготовленными, без публикации.

## Подготовлено 26.10.2026: доска сотрудников и задачи

Изменения находятся в исходниках; сервер, установщики и каналы обновлений
этим этапом не публиковались. Новый раздел «Доска сотрудников» доступен
руководителям и аналитикам. Таджикистан находится слева, Узбекистан справа;
неопределённая республика показана отдельным блоком. Под именем мелко видны
логин, статус доступа и подтверждения ПК/телефона. Последняя связь — время
обращения устройства, а не утверждение, что человек сейчас онлайн.

Добавление выбирает сотрудника из серверного справочника/текущих назначений
реестра. Уточнённый 27.10 сценарий начинается с кнопки «Убрать» и вопроса
об удалении профиля. При выборе «Убрать и удалить профиль» одна транзакция
отключает строку справочника, удаляет учётные данные и отзывает входы.
Договоры, факты и история задач сохраняются. Повторное
добавление не восстанавливает удалённые пароли или сеансы. Старое окно
подтверждения не может удалить пересозданную учётку: проверяется её числовой ID.

В «Задачах» руководитель выбирает исполнителя, описание и дату/время срока.
Руководитель и исполнитель добавляют заметки и этапы с указанием автора.
Сдать результат может только исполнитель после выполнения этапов; подтвердить
или вернуть с обязательным пояснением может назначивший руководитель.
Подтверждённая задача закрыта для правок. Аналитик просматривает историю всей
компании; задачи сотрудника доступны в настольных Харде и Софте. Новый экран
задач на телефоне в этот этап не входит.

Сервер проверяет актуальную область доступа, ревизию и номер операции.
В пределах открытого окна повтор потерянного запроса использует прежний номер.
Доска и задачи требуют связи: очереди для новых задач и их правок при закрытии
окна пока нет. Существующие защищённые очереди звонков/офисных записей сохранены.

Проверен 101 HTTP/SQLite/операционный сценарий, отдельно 42 сценария
регистрации и подтверждения доступа; TypeScript и сборка проходят.
Изолированный Electron-сценарий проверяет колонки, мелкий логин, отмену и
подтверждение удаления, добавление, постановку, этап, сдачу и подтверждение.
Снимки и квитанция находятся в `_local/team-work-2026-10-26/`.

## 3.2.6

В разделе «Обещания» руководителя видны Хард и Софт с отдельными счётчиками. При первом открытии непустой Софт выбирается, если Хард пуст; явный выбор сохраняется. У направлений отдельные фильтры таблицы и экспорт, ошибка загрузки показывается явно. Серверные расчёты и область доступа прежние.

Поставка состоит из четырёх продуктов: Хард, Софт, руководитель/СБ и аналитик.
Сборка установщика и совпадение исходников не доказывают запуск установленной
программы: библиотека updater может оказаться без транзитивных зависимостей.

Собирать из реального `hard-desk` с его собственным установленным деревом
`node_modules`. Копии проекта с junction на чужой `node_modules` дали неполное
дерево npm: сборщик только предупреждал о `name@undefined` и создавал EXE,
который завершал загрузку ошибкой `Cannot find module 'fs-extra'`.

```powershell
python -m pytest tests -ra
cd hard-desk
npm ci
npm run check
npm run test:queue
npm run test:transport
npm run test:links
npm run test:desktop
npm run test:runtime-deps
npm run build
node tools/installers.mjs
node tools/audit-installers.mjs
node tools/prepare-release.mjs --out ..\_local\release\3.1.7
node tools/verify-release.mjs ..\_local\release\3.1.7
```

Номер каталога берётся из текущего `package.json`. Ключ подписи находится
только в `_local/`; в комплект и Git он не входит. Сборка не публикует выпуск.

`installers.mjs` проверяет внутри ASAR все обязательные зависимости, их версии
и точки входа. `audit-installers.mjs` повторяет проверку по содержимому самого
раздаточного EXE, включая встроенный установщик, а также сверяет исходники,
вспомогательный C#-код и Python backend аналитика. `verify-release.mjs`
проверяет подписи Ed25519, размеры, хэши и отдельный канал каждого продукта.
Подпись updater не является Microsoft Authenticode.

После этого установить конечные EXE на Windows, сохранив профили. Изолированным
профилем проверить запуск каждого установленного продукта, формы входа,
переключение вкладок и запуск встроенного backend аналитика. Отдельно проверить
перенос прежнего входа, сохранность очереди/черновиков и работу после перезапуска.
Тесты Chromium, IPC, HTTP/SQLite и Excel запускаются только на синтетических данных.

Перед раздачей проверить рабочий HTTPS-origin и сервис-воркер PWA. На реальном
пилотном телефоне остаются GPS, камера, установка ярлыка и мобильная связь.
Новая PWA и другой порт — отдельные browser origins; очередь прежнего origin
должна быть отправлена до перехода. Рабочие книги и учётные данные не входят
в публичный комплект установщиков.
