# Хард — установка на сервер

Инструкция для системного администратора. Читать сверху вниз, ничего не
пропуская: пропущенных шагов здесь нет, лишних тоже.

Система собрана из трёх независимых частей — **единиц**. Каждая ставится своей
командой, живёт своей жизнью и обновляется отдельно от других.

| Единица | Каталог | Что делает | Обязательна? |
|---|---|---|---|
| **core** | `units/core` | приложение сотрудника, административное API для пульта, база, фотографии, Telegram-бот | **да** |
| **stt** | `units/stt` | распознавание голосовых комментариев | нет: без неё сотрудники вводят текст руками |
| **gps** | `units/gps` | порядок объезда по реальным дорогам | нет: без неё порядок точек считается упрощённо |

**Порядок установки не важен.** Единицы не ищут друг друга при старте и не
падают, если соседа нет. Связь появляется сама, когда сосед появляется:

- **core ↔ stt** — через общий docker-том `hard-stt-run`: в нём лежат сокет и
  токен службы речи. Приложение перечитывает токен на каждом запросе, поэтому
  поставленная позже речь подхватывается без перезапуска приложения.
- **core ↔ gps** — через общую docker-сеть `hard-net` по HTTP. Адреса
  маршрутизаторов вписываются в `.env` ядра; пустой адрес — просто упрощённый
  расчёт, а не ошибка.

Общие том и сеть создаёт `install.sh` любой из единиц — кто первый, тот и создал.

---

## Что нужно

| | |
|---|---|
| Сервер | 2–4 ядра, **4 ГБ памяти** (8 ГБ — если ставите речь и маршруты: речи отведено 2 ГБ, дорожный граф держит примерно половину своего объёма), от 100 ГБ диска |
| Система | любой Linux с Docker Engine и Docker Compose v2 (проверка: `docker compose version`) |
| Сеть | интернет при установке (образы и библиотеки). Дальше — только для Telegram, если он включён. **Сервер в закрытом контуре — см. раздел «Установка без интернета»: там установка идёт вообще без сети** |
| Домен | один поддомен компании с сертификатом — или открытые порты 80/443 для встроенного Caddy |

Диск расходуется в основном на фотографии — около 250 КБ на снимок; при девяти
сотрудниках это 4–5 ГБ в год.

---

## HTTPS обязателен

**Это единственное требование, ошибка в котором ломает всё.**

Приложение сотрудника — PWA. Три его главные способности браузер выдаёт только
по защищённому соединению: работа без интернета, камера (фото вручения) и
геопозиция (подтверждение, что сотрудник был на адресе). По `http://` браузер
отключит всё три **молча**: страница откроется и будет выглядеть рабочей.

Приложение слушает только `127.0.0.1:8080` (порт меняется в `.env` ядра,
`APP_PORT`). Перед ним ставится обратный прокси с сертификатом:

```nginx
server {
    listen 443 ssl http2;
    server_name hard.company.ru;

    ssl_certificate     /etc/ssl/company/fullchain.pem;
    ssl_certificate_key /etc/ssl/company/privkey.pem;

    client_max_body_size 30m;          # фотографии

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;           # фото по слабой мобильной сети
    }
}
```

**Своего прокси нет?** Встроенный включается в `.env` ядра: `DOMAIN=hard.company.ru`
и `COMPOSE_PROFILES=proxy`. Направьте DNS-запись домена на сервер, откройте
порты 80 и 443 и выполните `./update.sh` — Caddy сам получит сертификат
Let's Encrypt и будет его продлевать.

## Установка

### 1. Ядро — с него начинают

```bash
cd deploy/units/core
./install.sh              # проверит Docker, создаст .env, соберёт и запустит
nano .env                 # ADMIN_ID и MINIAPP_URL; BOT_TOKEN — если нужен Telegram
./update.sh               # применить настройки
```

`install.sh` безопасно запускать повторно: существующие `.env` и данные он не
трогает. Он же генерирует `ADMIN_API_KEY` — этот ключ нужен пульту аналитика.

После этого система уже работает. Дальше — по желанию.

### 2. Речь (если нужны голосовые комментарии)

Сначала **модель**. Она едет внутри образа, а не качается при первом старте:
служба речи в интернет не ходит вообще. Если каталог `stt/model/` в исходниках
пуст, подготовьте модель один раз — на этой же машине или на любой другой с
интернетом:

```bash
python tools/prepare_stt_model.py      # скачает ≈1,6 ГБ и переведёт в 0,8 ГБ
```

Скрипту нужен только docker: всё, что нужно для перевода весов, он делает в
контейнере. Готовый каталог `stt/model/` можно перевезти файлом на закрытую
машину — тогда там не понадобится ни интернет, ни этот скрипт.

Потом сама установка:

```bash
cd deploy/units/stt
./install.sh
```

Модель уже в образе, поэтому служба поднимается за секунды, а не за четверть
часа. Дольше всего идёт первая сборка образа.

Затем **включите голос в ядре**: в `deploy/units/core/.env` задайте
`VOICE_BACKEND=stt` и выполните там `./update.sh`.

### 3. Маршруты (если нужен порядок объезда по дорогам)

Сначала соберите дорожные графы — рецепт в [`geo/README.md`](geo/README.md);
это несколько часов машинного времени и около 10 ГБ диска. Готовые графы
кладутся в `units/gps/osrm/<страна>/`.

```bash
cd deploy/units/gps
./install.sh              # создаст .env из .env.example и поднимет то, что в нём выбрано
nano .env                 # COMPOSE_PROFILES=uz,tj — какие страны поднимать
./install.sh              # повторно: проверит графы и поднимет маршрутизаторы этих стран
```

**Порядок именно такой.** До первого запуска `install.sh` файла `.env` в
каталоге нет — есть только `.env.example`, из которого `install.sh` его и
делает. Если открыть `nano .env` раньше, редактор создаст пустой файл, а
`install.sh` увидит его и скажет «`.env` уже есть — оставляю как есть»: все
переменные (`COMPOSE_PROFILES`, `OSRM_GRAPH_*`, порты) вместе с пояснениями
пропадут. Повторный запуск `install.sh` безопасен: `.env` и графы он не трогает.
Позже правки `.env` применяются и короче — `./update.sh`.

Затем впишите адреса в `deploy/units/core/.env` и выполните там `./update.sh`:

```
OSRM_URL_UZ=http://osrm-uz:5000
OSRM_URL_TJ=http://osrm-tj:5000
OSRM_URL_RU=http://osrm-ru:5000
VROOM_URL=http://vroom:3000
```

Строки стран, которых нет, оставьте пустыми.

## Установка без интернета (закрытый контур)

Если у сервера нет выхода в сеть, обычная установка не состоится: сборка образа
ходит и за базовым образом, и за пакетами `pip`. Для этого случая есть отдельный
путь — образы собираются один раз на машине с интернетом, увозятся файлом и
заносятся в docker на месте.

Полностью описан в [`offline/README.md`](offline/README.md). Коротко:

```bash
# на машине с интернетом
cd deploy/offline && ./bundle.sh

# на закрытой машине (каталог с флешки)
./load.sh --deploy /opt/hard/deploy      # путь к исходникам системы на диске
```

`load.sh` ставит отметку офлайн-режима — после неё те же самые `install.sh` и
`update.sh` ничего не собирают и в сеть не ходят, а работают на привезённых
образах. Разовый запуск без отметки: `HARD_OFFLINE=1 ./update.sh`.

## Переезд на другой сервер

Живую систему **нельзя** перевозить копированием `data/` через `scp`: база
открыта приложением, а вместе с ней уедут токен бота, привязки пульта и адреса
старого сервера — на новом месте они превращаются в ложь и в лишние двери.

Для переезда есть отдельный сценарий, две команды — [`MIGRATION.md`](MIGRATION.md):

```bash
старый:  cd deploy/units/core && ./migrate.sh take
новый:   cd deploy/units/core && ./migrate.sh receive handover/hard-handover-*.tar
```

## Как проверить, что всё встало

В каждой единице есть своя проверка:

```bash
cd deploy/units/core && ./doctor.sh
cd deploy/units/stt  && ./doctor.sh      # если ставили
cd deploy/units/gps  && ./doctor.sh      # если ставили
```

Дальше — руками, по порядку. Первые три пункта проверяют сервер, остальные —
то, ради чего всё делалось:

1. `curl -I http://127.0.0.1:8080/` — ответ `200`.
2. Открыть `https://ваш-домен/` в браузере — открывается страница входа.
3. Пульт аналитика подключается по адресу сервера и `ADMIN_API_KEY` из `.env` ядра.
4. Получить персональную ссылку входа сотрудника: в пульте, раздел «Люди»,
   кнопка «Ссылка входа». Открыть её **на телефоне**, добавить на экран.
5. Открыть любую карточку и сделать фотографию — уходит за 1–3 секунды.
6. Включить авиарежим, заполнить карточку, выключить — данные уходят сами.
7. Нажать микрофон в комментарии и надиктовать фразу — появляется текст.

**Пункт 6 — главный.** Если он не работает, дело почти наверняка в HTTPS.

## Обновление и резервные копии

Обновляется каждая единица отдельно и независимо: заменили исходники новой
версией — и в нужном каталоге:

```bash
./update.sh
```

Данные при этом не трогаются: база и фотографии живут в `units/core/data`,
дорожные графы — в `units/gps/osrm`. Модель речи живёт внутри образа, поэтому
обновление единицы `stt` пересобирает образ вместе с ней — терять там нечего.

Копия базы (и удаление старых копий по `BACKUP_KEEP`):

```bash
cd deploy/units/core && ./backup.sh      # копии складываются в backups/
```

**Бэкапить нужно ровно один каталог — `units/core/data`.** Всё остальное
восстанавливается установкой заново.

Обратный ход — из копии обратно в работу:

```bash
cd deploy/units/core
./restore.sh backups/20260910T031500            # только база
./restore.sh backups/20260910T031500 --photos   # база и фотографии
```

Скрипт остановит приложение, отложит текущую базу рядом под именем
`data/hardbot.db.before-restore-*` и поднимет приложение снова. Восстановили не
то — тем же скриптом вернитесь на отложенную копию. Ключ `--yes` пропускает
вопрос о подтверждении: он нужен, когда команду выполняет не человек, а скрипт.

**Переезд на другой сервер — это не восстановление из копии.** Копия рассчитана
на ту же установку. Чтобы перенести работающую систему на другую машину, есть
отдельный порядок: [`MIGRATION.md`](MIGRATION.md).

## Если что-то не работает

| Что видно | Что это значит |
|---|---|
| `network hard-net declared as external, but could not be found` | запустили `docker compose` руками, минуя `./install.sh`. Лечится: `docker network create hard-net` и `docker volume create hard-stt-run` |
| Скрипт сказал «контейнер падает и перезапускается по кругу» | это не «ещё грузится», ждать бесполезно. Причина — в последних строках `docker compose logs --tail=50 <сервис>`; почти всегда ошибка в `.env` |
| `stt` перезапускается по кругу, в журнале «модели нет» | образ собран без модели. Подготовьте её (`python tools/prepare_stt_model.py`) и пересоберите: `cd deploy/units/stt && ./update.sh` |
| Приложение открывается, но нет камеры/гео/офлайна | нет HTTPS. См. раздел выше |
| Голос не появляется | в `.env` ядра `VOICE_BACKEND` должен быть `stt`, и должна быть поставлена единица `stt` |
| Порт занят | поменяйте `APP_PORT` в `.env` ядра и `./update.sh` |

Сменить токен службы речи (ядро подхватит новый само):

```bash
docker run --rm -v hard-stt-run:/run/stt hard-stt rm /run/stt/stt.token
cd deploy/units/stt && ./update.sh
```

---

## Чего не делать

- **Не удалять общий том**: `docker volume rm hard-stt-run` разрывает связь
  ядра со службой речи. Пересоздаётся установкой `stt` заново.
- **Не публиковать порт приложения наружу** (`0.0.0.0:8080`) — оно рассчитано
  на работу за прокси с HTTPS.
- **Не ставить лимит памяти приложению**: при загрузке большого реестра оно
  кратковременно берёт заметно больше обычных 300 МБ. С потолком 768 МБ
  контейнер убивало пять раз подряд. Если лимит требуется политикой — не ниже 2 ГБ.
- **Не редактировать файлы в `data/`** руками. База открыта приложением.

## Что где лежит

```
deploy/
  README.md            этот файл
  MIGRATION.md         переезд живой системы на другой сервер
  doctor.sh            диагностика всех трёх единиц сразу
  _lib.sh              общие функции скриптов всех единиц
  _actions.sh          общие шаги установки, обновления и диагностики
  env_manifest.json    все переменные окружения с пояснениями (сверяется тестом)
  env_manifest.py      проверка .env против манифеста: python env_manifest.py check
  geo/                 рецепты сборки дорожных графов и тайлов карты
  offline/             установка в закрытом контуре: bundle.sh, load.sh, README.md
  units/
    core/              приложение: compose, .env, data/, backups/, Caddyfile, migrate.sh
    stt/               речь: compose, .env, models/ (кэш; модель едет в stt/model)
    gps/               маршруты: compose, .env, osrm/, vroom/
```

В каждой единице: `install.sh`, `update.sh`, `doctor.sh`, `.env.example`
(образец настроек с пояснениями) и `unit.conf` — описание состава единицы,
его правят только вместе с compose-файлом.

Рядом с `deploy/`, в корне исходников, пригодятся ещё два файла:

- `requirements-dev.txt` — всё, что нужно, чтобы прогнать тесты
  (`pip install -r requirements-dev.txt`, затем `python -m pytest`);
- `tools/prepare_stt_model.py` — подготовка модели распознавания речи.
