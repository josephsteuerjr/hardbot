# Адверсарное ревью обмена — 03.11.2026

Проверены действующий сервер, исходники установленного Аналитика, исполняемые
скрипты сборки-разборки и фактические книги. Проверка направлена на потерю,
откат, неверное присвоение и повтор данных. Это не обещание отсутствия всех
возможных дефектов и не аудит безопасности всей инфраструктуры.

Исправления сервера установлены. Аналитик 3.2.21 установлен владельцу,
опубликован в подписанном канале обновлений и доставлен владельцу и Клинову.
У Клинова заменён рабочий Python-комплект сборки-разборки; 92 файла поставки
проверены по SHA-256. Старый установщик Аналитика у Клинова удалён после
проверки нового. Резервные копии прежнего кода находятся локально.

## Подтверждённые дефекты и исправления

| Приоритет | Ошибка | Исправление |
|---|---|---|
| Критический | Совпадение дня/статуса позволяло принять старые поля Excel за исправление свежего звонка | Убран слабый якорь; входящая дата ручной правки проверяется отдельно от уже сохранённой. Тот же день, отсутствующая или будущая дата не разрешают откат |
| Критический | Один номер договора другого кредитора мог перезаписать существующую карточку | Импорт останавливается при несовпадении кредитора, даже если в самом файле нет дублей |
| Высокий | Разные строки связанных договоров могли противоречиво исправить один результат | Противоречие откатывает весь импорт вместо правила «последняя строка победила» |
| Высокий | Старая доставка любого комментария считалась достаточной для очистки нового | Проверяются точный текст и дата соответствующего события; защищённые комментарии отражаются в результате импорта |
| Высокий | Повтор звонка с тем же ID и другим содержимым принимался старым клиентом без ревизии | Изменённое содержимое повторной операции отклоняется; производные серверные поля исключены из сравнения |
| Высокий | Решение «оставить в файле» переживало изменение сравниваемых значений | Выбор связан с точными значениями; повторная проверка выполняется до записи и после неё |
| Критический | В общих колонках Хард безусловно побеждал Софт | Приоритет роли удалён; неразрешимые противоречия блокируют публикацию. Группа прогноза переносится целиком |
| Критический | Закрепление очищало статусы звонков и ставило «Не обработан» поверх фактов | Меняются назначение и его дата; результаты работы сохраняются |
| Критический | Ошибка чтения книги могла завершиться успешной разборкой остальных данных | Ошибка прерывает цикл с ненулевым кодом; сначала сборка прежних закреплений, затем смена назначений |
| Высокий | Файл находили по точному имени, роль — по подстроке пути | Восстановлены проверенные правила активных книг, выбранных датированных файлов, вложенных портфелей и определения профиля |
| Высокий | Телефоны и идентификаторы менялись при записи Excel | Текстовые поля форматируются до записи; нули, разделители и длинные значения сохраняются |
| Высокий | Между сборкой и разборкой сотрудник мог изменить книгу | Проверяется та же версия источника при публикации; изменение общего реестра также останавливает дальнейшую разборку |
| Высокий | Старый комментарий мог вернуться после очистки нового месяца | Проекция прежнего месяца не заполняет очищенный комментарий текущего месяца |
| Высокий | На шаре запускался комплект, отличный от проверенной поставки | Добавлена проверка полного манифеста перед этапами; смешанные версии не запускаются |

Общие поля оплат больше не собираются из личных копий поверх учётного общего
реестра. Задание закрепления с неоднозначным номером договора останавливается.
Пустые значения, неизвестные даты и неизвестный результат публикации не
считаются доказательством успешной обработки.

## Проверка фактических данных

Проверены 57 личных книг и общий реестр. Найдено 16 спорных расхождений:
три полных комментария в личных книгах совпали с текущим сервером и содержали
весь прежний текст общего реестра; в остальных случаях подтверждено сохранение
существующего значения. Среди них — список двух телефонов, превращённый Excel
в число с потерей точности, и пустые/сброшенные результаты закрепления.

Для этой конкретной версии файлов подготовлена сверка. Она неприменима после
изменения SHA общего реестра или любой исходной книги. Реальные рабочие книги
в рамках ревью не переписывались; проверка выполняется на локальной копии.
Новая сборка и импорт не запускаются повторно по старой квитанции.

Полный прогон на копии дополнительно выявил шесть недатированных комментариев,
которые возвращались бы в очищенное поле нового месяца. Сервер подтвердил,
что это текст событий октября. Их сохранение в очищенном состоянии также
включено в точную сверку: всего 22 решения, из них три дополняют комментарий
общего реестра, 19 сохраняют существующее значение. История приложения остаётся
доступной; текущая месячная проекция не подменяет её.

## Проверки

* 90 серверных проверок: откат устаревшим Excel, кредитор, связанные договоры,
  замена/защита комментариев, повтор операции, временная граница рабочего дня.
* 247 клиентских регрессий: очередь, доставка, открытые книги, пропуски,
  конфликты, ручные правки и импорт.
* Отдельные проверки нового сборщика: идентичность, права источника, даты,
  целостность группы прогноза, оплата, смена месяца и устаревшее решение.
* Точный собранный EXE: аудит исходников/состава, подпись, XLSB, потеря ответа,
  остановка и восстановление процесса, интерфейс очереди.
* Настоящий Excel: разборка → ручная правка → сборка → повторная разборка;
  сохранение текста телефонов, дат, метаданных расчёта и блокировка потери
  работы прежнего ответственного.

Для сборщика прошли 30 модульных и 29 нативных проверок. На копии настоящего
общего реестра сверены 4 054 446 ячеек. Три согласованные правки относятся к
комментариям; остальные значения и формулы сохранены. Excel пересчитал 6 921
кэшированное значение формулы «Остаток дней в работе» при переходе суток;
сами формулы не менялись. Копии формул, макросов и метаданных расчёта проверены
до разрешения публикации.

Проверка обновления владельца подтвердила сохранение функционального профиля
и всей существующей очереди. Сервер обновлялся с отдельной резервной копией,
сохранением текущих томов, аккаунтов, конфигурации и других сервисов.

## Что требует нового контракта данных

Дневная отметка ручной правки — ограничение совместимости старого Excel.
Она не заменяет версию конкретного поля и не даёт полного доказательства
порядка правок. Без такого доказательства нельзя обещать автоматическое
разрешение любого конфликта. Для старого формата сохраняются строгая сверка,
остановка при неоднозначности и решения для точного снимка.

Глобальный номер договора пока остаётся ключом старой БД. Проверка кредитора
закрывает перезапись, но полноценная поддержка одинаковых номеров у разных
кредиторов требует миграции на внутренний ID договора. Аналогично, новая CRM
должна отделить человека, договор, назначение, событие и отчётную проекцию.

У всех видов событий нужен единый механизм ID операции, отпечатка запроса,
фиксированного набора договоров и воспроизводимой квитанции. Этот выпуск
усиливает проверку звонка; он не объявляет все старые конечные точки полностью
переведёнными на новый протокол.

Полную схему перехода, роли, вкладки, скрипт, правила Excel и критерии пилота
описывает [проект единого реестра и CRM](unified-registry-crm.md).
