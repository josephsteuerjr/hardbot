# Начни отсюда

Развёртывание системы «Хард» на новой машине. Один путь сверху вниз, без
развилок. После каждого шага написано, как понять, что он получился; если не
получился — идти в [ЕСЛИ НЕ РАБОТАЕТ.md](ЕСЛИ%20НЕ%20РАБОТАЕТ.md), а не дальше.

Инженером быть не нужно. Нужно выполнять команды по порядку и читать, что
они отвечают.

---

## Что вы разворачиваете

Приложение для сотрудника, который ездит по адресам: список должников на день,
порядок объезда, карта, фотография вручения, голосовой комментарий, работа без
связи. Плюс сводка для руководителя и пульт для аналитика.

Система состоит из трёх частей — **единиц**. Обязательна одна.

* **core** — само приложение, база, фотографии. Без неё ничего нет.
* **stt** — распознавание голоса. Без неё сотрудники печатают руками.
* **gps** — порядок объезда по настоящим дорогам. Без неё порядок считается
  упрощённо, «по прямой».

Ставятся в любом порядке, друг друга не ждут, по отдельности не ломаются.

---

## Шаг 1. Проверить машину

```bash
bash "0-проверка/preflight.sh"
```

Скрипт ничего не устанавливает и не меняет. Он смотрит систему, время, docker,
свободное место и то, куда машину выпускают в сеть.

**Получилось, если** в конце написано «отказов 0». Строки `[ !! ]` — это не
ваша работа и не чинится командами: каждая означает пункт к ИТ-службе, и они
перечислены в [ТРЕБОВАНИЯ-ИТ.md](ТРЕБОВАНИЯ-ИТ.md). Сравнить можно с
`0-проверка/эталон.txt` — это вывод на заведомо здоровой машине.

---

## Шаг 2. Разложить систему на диск

```bash
sudo mkdir -p /opt/hard && sudo cp -a "2-система/." /opt/hard/
```

Путь `/opt/hard` выбран не случайно: **в нём нет пробелов и кириллицы**. Служба
обслуживания на путях с пробелами не запускается.

Затем вернуть скриптам право запуска — при копировании с флешки или из архива
оно теряется:

```bash
sudo chmod +x /opt/hard/deploy/*.sh /opt/hard/deploy/units/*/*.sh
```

**Получилось, если** `ls -l /opt/hard/deploy/units/core/install.sh` показывает
`x` в правах.

---

## Шаг 3. Занести образы

Образ — это уже собранная система: нужная версия питона, все библиотеки, код, а
у речи внутри ещё и модель распознавания. Ничего не скачивается и не собирается.

```bash
cd "1-образы" && sudo ./load.sh --deploy /opt/hard/deploy
```

**Получилось, если** скрипт перечислил занесённые образы и поставил отметку
офлайн-режима. С этой отметки установка и обновление в интернет не ходят вовсе.

---

## Шаг 4. Поставить ядро

```bash
cd /opt/hard/deploy/units/core && sudo ./install.sh
```

Скрипт проверит docker, создаст `.env` из образца, поднимет приложение и
напечатает `ADMIN_API_KEY` — **этот ключ нужен пульту аналитика, сохраните
его**. Запускать скрипт повторно безопасно: данные и настройки он не трогает.

Дальше откройте `.env` и заполните два поля:

* `ADMIN_ID` — телеграм-идентификатор владельца системы;
* `MINIAPP_URL` — публичный адрес, по которому приложение открывается у
  сотрудников; **строго `https://`, без косой черты в конце**.

Про адрес — шаг 7; если его ещё нет, оставьте поле пустым и вернитесь сюда
позже. Применить правки:

```bash
sudo ./update.sh
```

**Получилось, если** `curl -I http://127.0.0.1:8080/` отвечает `200`.

---

## Шаг 5. Речь

```bash
cd /opt/hard/deploy/units/stt && sudo ./install.sh
```

Модель уже внутри образа, поэтому служба поднимается за секунды и в интернет не
выходит. Затем включить голос в ядре — в `/opt/hard/deploy/units/core/.env`
задать `VOICE_BACKEND=stt` и там же выполнить `sudo ./update.sh`.

**Получилось, если** `./doctor.sh` в каталоге `stt` не нашёл замечаний.

---

## Шаг 6. Ресурсы: карта, адреса, дороги

Это не код и не данные — это гигабайты, которые нельзя собрать на месте за
разумное время. Их привозят готовыми, они лежат в `3-ресурсы`.

```bash
cd "3-ресурсы" && sha256sum -c SHA256SUMS
sudo cp map/basemap.pmtiles /opt/hard/deploy/units/core/data/
sudo cp -a geonames /opt/hard/deploy/units/core/data/
sudo cp -a osrm/* /opt/hard/deploy/units/gps/osrm/
```

**Получилось, если** проверка сумм не ругнулась ни на один файл.

Без карты система поставится, все проверки пройдут, а карта молча уйдёт на
интернет-подложку — это одна из самых неприятных тихих поломок, потому что
выглядит как «просто медленно».

Дороги нужны только единице gps:

```bash
cd /opt/hard/deploy/units/gps && sudo ./install.sh
```

Затем в `.env` ядра вписать адреса маршрутизаторов (строки стран, которых нет,
оставить пустыми) и выполнить там `sudo ./update.sh`:

```
OSRM_URL_UZ=http://osrm-uz:5000
OSRM_URL_RU=http://osrm-ru:5000
VROOM_URL=http://vroom:3000
```

## Шаг 7. Впустить людей снаружи

**Это единственный шаг, который вы не можете сделать сами, и без него система
бесполезна.** Приложение слушает только `127.0.0.1` — телефон сотрудника до
него не достучится.

Нужен публичный адрес с сертификатом. Кто его даёт — ИТ-служба: правило
публикации на 443, запись в DNS, сертификат. Формулировка для них — в
[ТРЕБОВАНИЯ-ИТ.md](ТРЕБОВАНИЯ-ИТ.md).

**HTTPS обязателен, и его отсутствие ломает всё молча.** Камеру, геопозицию и
работу без связи браузер выдаёт только по защищённому соединению. По `http://`
страница откроется и будет выглядеть рабочей, а фотофиксации, подтверждения
выезда и офлайна не будет.

Когда адрес есть — впишите его в `MINIAPP_URL` и выполните `./update.sh` в
каталоге ядра. **Перезапуск обязателен**: кнопка в боте проставляется только
при старте.

**Получилось, если** этот адрес открывается с телефона по мобильному
интернету, а не только из офисной сети.

---

## Шаг 8. Убедиться, что работает то, ради чего всё делалось

По порядку, ничего не пропуская:

1. `cd /opt/hard/deploy && ./doctor.sh` — замечаний нет.
2. Открыть адрес в браузере телефона — появляется страница входа.
3. Подключить пульт аналитика: адрес сервера и `ADMIN_API_KEY` из шага 4.
4. В пульте, раздел «Люди», кнопка «Ссылка входа» — открыть её **на телефоне**
   и добавить приложение на экран.
5. Открыть любую карточку и сделать фотографию — уходит за одну-три секунды.
6. Включить авиарежим, заполнить карточку, выключить — данные уходят сами.
7. Нажать микрофон в комментарии и надиктовать фразу — появляется текст.
8. Открыть карту — она рисуется своими тайлами, а не подгружается из интернета.

**Пункт 6 — главный.** Если он не работает, дело почти наверняка в HTTPS.

## Шаг 9. Как жить дальше

Установка занимает полчаса, а живёт система годами, поэтому это самый важный
раздел.

**Панель обслуживания** — `https://ваш-адрес/ops/`. Оттуда видно состояние всех
трёх единиц и делается всё, за чем иначе пришлось бы идти в консоль:
диагностика, журнал, копия базы, перезапуск, обновление, восстановление. Вход —
одноразовым кодом, который выдают на сервере:

```bash
cd /opt/hard/deploy/units/core && sudo docker compose exec -T app python /app/admin_access.py issue --name "Инженер" --role engineer
```

**Резервные копии.** Копировать нужно ровно один каталог —
`units/core/data`. Всё остальное восстанавливается установкой заново.

```bash
cd /opt/hard/deploy/units/core && sudo ./backup.sh
```

Поставьте это в расписание. Диск тратится в основном на фотографии — около
250 КБ на снимок.

**Обновление.** Заменили исходники новой версией — и `./update.sh` в каталоге
единицы. Данные при этом не трогаются.

**Чего не делать:** не публиковать порт приложения наружу минуя прокси с
сертификатом; не ставить контейнеру приложения лимит памяти ниже 2 ГБ (при
загрузке реестра он кратковременно берёт больше обычного); не править файлы в
`data/` руками — база открыта приложением.
