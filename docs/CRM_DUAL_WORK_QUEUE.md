# Единая рабочая очередь

Кандидат 3.3.0-pilot.4 добавляет «Мой портфель» рядом с общим просмотром клиентов. Одна строка представляет договор с устойчивым идентификатором, а виды работы определяются действующими закреплениями и открытыми поручениями. Два вида работы не создают две строки или двойную сумму долга.

Фильтры: все договоры, звонки, выезды, оба вида; для курьера — доставка. Счётчики показывают полный личный портфель, а результат поиска и сумма относятся к отфильтрованным договорам. Валюты считаются отдельно, неизвестная сумма/валюта отмечается. Страницы содержат по 100 договоров; фильтрация предшествует разбиению на страницы.

Сотрудник открывает собственную очередь. Руководитель и аналитик выбирают сотрудника только в пределах серверной области доступа. Просмотр чужой очереди не заменяет текущего автора и не предоставляет право действовать от имени выбранного человека. Команды из карточки сохраняют действующие проверки прав.

В каждой строке отдельно показаны результаты звонка и выезда. Фильтр и выбранный сотрудник сохраняются в защищённом состоянии текущего входа; возврат из карточки сохраняет страницу и поиск. «Все клиенты» сохраняет общую видимость, включая клиентов вне личной рабочей очереди.

GET `work-portfolio` поддерживает `employee_uuid`, `work=all|call|visit|both|delivery`, `search`, `offset`, `limit` (до 200). Маршрут реализован в общем API и локальном проверочном сервере. Ответ не меняет закрепления и не создаёт рабочие события.

Проверка включает набор 429 договоров только для звонка, 6 только для выезда и 34 с обоими видами работы: 469 уникальных договоров. Реальные лица, книги и результаты сверки находятся только в локальной операционной памяти.

Изменение добавляет рабочее представление существующего общего контура. Начальная загрузка данных не повторяется; массовый переход и обмен со старыми приложениями требуют отдельной сверки.
