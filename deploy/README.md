# Развёртывание системы выездного взыскания

Инструкция для системного администратора. Развёртывание занимает около получаса,
из которых двадцать минут — сборка образа.

---

## Что нужно

| | |
|---|---|
| Сервер | 4 ядра, 8 ГБ памяти, от 100 ГБ диска |
| Система | любой Linux с Docker и Docker Compose v2 |
| Сеть | обычный доступ в интернет |
| Домен | один поддомен компании с сертификатом |

Диск расходуется в основном на фотографии — около 250 КБ на снимок. При девяти
сотрудниках это порядка 4–5 ГБ в год.

---

## HTTPS обязателен

**Это единственное требование, ошибка в котором ломает всё.**

Приложение сотрудника — это PWA. Три его ключевых способности браузер выдаёт
только на защищённом соединении:

- работа без интернета (данные копятся на телефоне и уходят при связи);
- доступ к камере — фотографии вручения;
- доступ к геопозиции — подтверждение, что сотрудник был на адресе.

По `http://` браузер отключит всё три молча: приложение откроется и будет
выглядеть рабочим, но фото и геолокация работать не будут, а без сети оно
не запустится вообще.

Поэтому перед сервисом ставится обратный прокси с сертификатом — nginx, Caddy,
Traefik, что принято в компании. Сам сервис слушает только localhost.

Пример для nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name vzyskanie.company.ru;

    ssl_certificate     /etc/ssl/company/fullchain.pem;
    ssl_certificate_key /etc/ssl/company/privkey.pem;

    client_max_body_size 30m;          # фотографии

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;           # загрузка фото по слабой мобильной сети
    }
}
```

## Установка

```bash
# 1. Разложить файлы проекта: рядом должны лежать папки hardbot/ и deploy/
cd deploy

# 2. Подготовить настройки
cp .env.example .env
nano .env                    # заполнить четыре обязательных значения

# 3. Собрать и запустить
docker compose up -d --build

# 4. Убедиться, что поднялось
docker compose ps            # ожидается: healthy
docker compose logs -f bot   # ожидается: «Бот запущен» и «Миниапп слушает»
```

Каталог `data/` создастся сам при первом запуске.

---

## Проверка после установки

1. Открыть `https://ваш-домен/` в браузере — должна открыться страница входа.
2. Написать боту в мессенджере слово `ссылка` — придёт персональная ссылка входа.
3. Открыть её **на телефоне**, добавить приложение на экран.
4. Открыть любую карточку, сделать фотографию. Она должна уйти за 1–3 секунды.
5. Включить на телефоне авиарежим, заполнить карточку, выключить авиарежим —
   данные должны уйти сами.

Пятый пункт — главный. Если он не работает, почти наверняка дело в HTTPS.

## Обновление

```bash
cd deploy
docker compose down
# заменить содержимое ../hardbot новой версией
docker compose up -d --build
```

Данные при этом не затрагиваются: они лежат в `data/`, отдельно от образа.

**Перед каждым обновлением снимайте копию базы** — см. следующий раздел. Это
занимает секунду и один раз уже спасало.

---

## Резервное копирование

Копировать нужно каталог `data/` целиком. База внутри него работает под нагрузкой,
поэтому обычное копирование файла может дать несогласованный снимок. Правильный
способ:

```bash
docker compose exec -T bot python -c "
import sqlite3, time
src = sqlite3.connect('/data/hardbot.db')
dst = sqlite3.connect('/data/backups/hardbot-%s.db' % time.strftime('%Y%m%dT%H%M%S'))
with dst: src.backup(dst)
print('готово')
"
```

Фотографии (`data/photos/`) копируются обычным способом — они не меняются
после записи.

Рекомендуемый режим: ежедневная копия базы, еженедельная — фотографий.

## Что не входит в базовую установку

Обе возможности необязательны, система без них работает полностью.

**Маршрутизация по картам** — подсказывает порядок объезда с учётом дорог.
Без неё порядок считается упрощённо. Требует отдельного сервиса OSRM и
подготовленного графа дорог страны, около 1 ГБ памяти на страну. Заготовка —
в конце `docker-compose.yml`.

**Распознавание голосовых комментариев** — сотрудник надиктовывает текст вместо
набора. Требует отдельно развёрнутой модели распознавания речи, около 3,5 ГБ
памяти. По умолчанию выключено (`VOICE_BACKEND=off`).

---

## Чего не делать

**Не ставить лимит памяти контейнеру.** При обычной работе сервис занимает около
330 МБ, но при загрузке большого реестра кратковременно берёт заметно больше.
С потолком 768 МБ контейнер убивало нехваткой памяти пять раз подряд. Если
ограничение требуется политикой — не ниже 2 ГБ.

**Не публиковать порт 8080 наружу.** Сервис рассчитан на работу за обратным
прокси и сам сертификат не обслуживает.

**Не хранить `.env` в системе контроля версий.** В нём токен бота и ключ
административного API.

---

## Если что-то не работает

| Симптом | Где смотреть |
|---|---|
| Контейнер не становится healthy | `docker compose logs bot` — обычно не заполнен `BOT_TOKEN` |
| Страница открывается, фото не отправляются | Проверить HTTPS и `client_max_body_size` в прокси |
| Приложение не работает без сети | Почти всегда HTTPS: по http браузер отключает автономный режим |
| Сотрудник не получает ссылку | Он не привязан. Привязка подтверждается владельцем при `BIND_APPROVAL=1` |
| Кончается место | `du -sh data/photos` — основной рост здесь |

Журнал сервиса: `docker compose logs --since=1h bot`
