# Пульт «Контур · Выезды»

**Актуальный пульт — `pult.py` (Python/Tkinter).** Запуск: двойной клик
`Пульт.bat` (или `python pult.py`). High-DPI, дизайн «Контур» (слоновая
кость + графит), все разделы: Сводка / Реестр / Приоритет / Люди /
Руководители / Активность / Подключение.

## Файлы

| Файл | Назначение |
|---|---|
| `pult.py` | Сам пульт (Tkinter): safe export и read-only preview enrichment; прямой master-import и legacy Excel write-кнопки на ограниченный тест закрыты; personal → bot batch отсутствует |
| `enrich.py` | Библиотека доказуемого обогащения: пишет только proven bot-поля, проверяет snapshot/file map/contract, сохраняет ручной текст и создаёт backup. Запуск записи разрешён только как evidence-bound стадия утверждённого цикла, не произвольной Tk-кнопкой |
| `limited_test_import.py` | Узкий двухфазный CLI для опубликованного master и утверждённого `test_subset`: создаёт immutable proof/request, затем после root-регистрации exact proof выполняет подтверждённый HTTPS-import; `registry_cycle` не запускает |
| `razbros.py` | **LEGACY, запись заблокирована.** Старый full-copy/filter разброс оставлен для анализа/предпросмотра; штатная публикация выполняется только через `registry_cycle` |
| `repair_false_enrichment.py` | Двухфазная точечная починка старых артефактов ложного обогащения: dry-run JSON+TXT → повторная сверка → атомарная замена проверенной копией |
| `Пульт.bat` | Запуск без консоли (pythonw) |
| `настройки пульта.json` | Адрес/ключ сервера, последние папки — создаётся сам |
| `dist/`, `src-tauri/` | **Легаси** — старый Tauri-пульт (Rust). Не развивается; оставлен как референс дизайна |

## Выгрузка: обогащение и слепок

- **Импорт опубликованного master** — единственный штатный вход в hardbot.
  Двухфазный CLI принимает только exact лист `Портфели`, сверяет контракт и
  прикладывает source proof: digest переданного grid, SHA файла и complete
  receipt/journal совпавшей `registry_cycle`-публикации. Одной метки
  `source_kind=published_master` недостаточно. Личные ФИО.xlsb пульт в БД не
  загружает: ручная/офисная правка идёт personal → `registry_cycle` →
  опубликованный master → explicit master import. Для завершённого визита
  «Общий результат» принимается только при совпавшей «Дате выезда» и
  reverse-map-ится во внутренний результат визита; call-status/call-comment
  остаются отдельными call-полями. Tk-кнопка прямого импорта на ограниченный
  тест fail-closed: она не открывает файл и не делает API-запрос.

- **Обогащение реестров выездников** — разрешённый обратный путь, но на
  ограниченный тест Tk-пульт показывает только read-only preview. Кнопки
  массовой записи и «Обогатить один файл» возвращают операторский STOP до
  file picker/Excel/API. Запись выполняется отдельно как evidence-bound
  стадия утверждённого цикла по exact snapshot и file-map. В каждый выбранный
  personal-файл точечно дописываются только кейсы его сотрудника. Маркер
  «кейс заполнен» — отдельный provenance-снимок
  завершённого визита, который обычный импорт реестра создать не может;
  пишутся только столбцы формы визита: результат выезда идёт в «Общий
  результат», наводки/новые номера — в «Доп. Адрес/Доп.Номер», плюс с кем
  контакт, договорённость, кто на адресе, местоположение, цель приезда,
  комментарий и дата. «Статус звонка» и «комментарий звонка» обогащение
  не трогает. Уже написанный комментарий выезда сохраняется, новый текст
  дополняется идемпотентно. Системные значения из импорта
  («Не обработан» и т.п.) в файлы не тащатся. Рядом с каждым изменённым
  файлом создаётся резервная копия.
- **Реестр целиком** — новый xlsx-слепок БД сервера: типизированные
  даты/суммы, автофильтр. Для сверки; это слепок БД, а не твой файл.

## Импорт опубликованного master

После уже завершённого и проверенного `registry_cycle` оператор создаёт
приватный request, не запуская новый цикл:

```powershell
python pult\limited_test_import.py prepare-published-master `
  --workbook "<published-master.xlsx>" `
  --workspace "_local\registry_cycle_v2" `
  --output-dir "<новая-приватная-папка>"
```

CLI принимает только глобально новейшую complete publication, immutable
workbook и exact publication/file/grid proof. Любой незавершённый journal в
workspace блокирует prepare, даже если предыдущий master был complete. Затем
`proof.json` передаётся root на сервер, регистрируется как
`published_master`, и тот же `request.json` применяется общей командой
`apply`, показанной ниже.

## Загрузка утверждённой выборки после очистки

Оператор заранее создаёт новый приватный каталог с exact request/proof.
`--scope` обязан перечислять все и только строки книги:

```powershell
python pult\limited_test_import.py prepare `
  --workbook "<subset.xlsx>" `
  --approval-id "<approval-id>" `
  --scope '[{"contract_id":"<КД>","responsible":"<ФИО>"}]' `
  --output-dir "<новая-папка>"
```

Команда перечитывает стабильную копию книги, применяет тот же машинный
контракт и parser, что сервер, и печатает `proof_digest`, но не обращается к
сети. Затем администратор передаёт `proof.json` в production runtime и
одноразово регистрирует его без HTTP:

```bash
docker compose exec -T bot python /app/import_authorization.py register \
  --source-kind test_subset \
  --proof /data/backups/<private-import-dir>/proof.json
```

Для опубликованного master та же команда получает
`--source-kind published_master`. Только после сверки printed digest оператор
отправляет неизменившийся request:

```powershell
python pult\limited_test_import.py apply `
  --request "<новая-папка>\request.json" `
  --settings "pult\настройки пульта.json" `
  --confirm-proof-digest "<digest>"
```

Незарегистрированный/просроченный proof, другая книга/scope, повторно
использованный каталог, неверный digest или не-HTTPS production URL дают
`STOP`. Текущий exact replay возвращается как явный zero-write; для нового
состояния нужен новый approval/proof. HTTP redirect запрещён, поэтому
`X-Admin-Key` не может автоматически уйти на другой origin.

Старые кнопки очистки Tk/Tauri отключены. Legacy `/admin/reset` всегда
возвращает `409`; единственный допустимый путь очистки — evidence-bound
`_local/reset_hardbot2_for_limited_test.py` после snapshot/clearance.

## Починка артефактов старого обогащения

Не откатывай личный реестр целиком и не выбирай копию по памяти. На компьютере,
где доступен сетевой корень реестров, сначала запусти только dry-run:

```powershell
python repair_false_enrichment.py --base "U:\rbr\Развитие СНГ"
```

Скрипт сопоставит текущий файл со всеми соседними копиями
`(до обогащения DD.MM HH-MM)`, исключит подтверждённые визиты бота и сформирует
TXT+JSON. Ячейка попадает в план только при доказанном переходе к точному raw-
значению сервера и только если после этого её не правили руками. После просмотра
TXT применяется именно созданный неизменившийся JSON:

```powershell
python repair_false_enrichment.py --apply "путь\к\false-enrichment-....json"
```

При применении оригинал не открывается в Excel: изменения делаются во временной
копии, копия перечитывается и проверяется, затем рядом атомарно создаётся
`(до починки ложного обогащения ...)`, и лишь после этого оригинал заменяется.
Если сервер, файл или план успели измениться, весь такой файл пропускается.
