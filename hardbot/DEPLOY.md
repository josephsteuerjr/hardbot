# Деплой и эксплуатация — практический runbook

Короткая шпаргалка «как выкатить и как переключить бота». Инфра-детали ИБ — в
`docs/security/11-deployment-infra.md`; здесь — операционные шаги.

## 1. Выкатка кода на сервер (Docker)

Сервер: `/opt/hardbot`, контейнер `bot` (aiogram-поллинг + мини-апп на `:8080`),
наружу — Caddy/Cloudflare даёт публичный https (= `MINIAPP_URL`).

```bash
# на сервере, в /opt/hardbot
git pull
docker compose up -d --build     # пересборка + рестарт; данные в ./data переживают
docker compose logs -f bot       # проверить старт (миниапп слушает 0.0.0.0:8080)
```

`.env` (не в git) — минимум:

```
BOT_TOKEN=<от @BotFather>
ADMIN_ID=<telegram_id владельца>
MINIAPP_URL=<публичный https-адрес мини-аппы>   # пусто → кнопка «Приложение» не ставится
ADMIN_API_KEY=<любой секрет>                     # нужен пульту для admin-API
```

## 2. Переключение на другой бот (из пульта, без консоли)

Пульт → раздел **Подключение** → карточка **Токен бота**:

1. Вставить новый токен → **Сменить бота** (пишется в durable-настройки БД + `.env`).
2. **Перезапустить бота** (или подтвердить рестарт в диалоге после смены).

Как это работает:
- `app.py` на старте берёт токен **сперва из настроек БД** (`settings.bot_token`,
  том `/data` — переживает рестарт и пересборку контейнера), иначе из `.env`.
- `POST /admin/restart` (под `ADMIN_API_KEY`) делает плановый `os._exit(0)`;
  супервизор (`docker-compose restart: unless-stopped`) поднимает процесс заново.
- На старте бот сам ставит menu-button мини-аппы новому боту
  (`set_chat_menu_button`, если задан `MINIAPP_URL`) — «развёртывание мини-аппы в
  новом боте» происходит автоматически.

> ⚠️ **Один токен = один запущенный бот.** Telegram отдаёт апдейты только одному
> поллеру. Нельзя одновременно держать боевого бота и на VPS, и локально с **одним
> и тем же токеном** — второй оборвёт первого (конфликт getUpdates). Перед стартом
> VPS-бота останови локального (или наоборот), либо используй разные токены.

## 2a. Актуальная вечерняя выкладка hardbot2 + собственный Whisper

Боевой второй инстанс обновляется только штатным локальным скриптом из корня
проекта. Он не заливает `.env`, compose и данные и отказывается стартовать, если
конкурирующий `/opt/hardbot` уже поднят.

Перед первой выкладкой пакета 2026-07-21 один раз отделить Whisper hardbot2 от
общего каталога Praxis:

```powershell
python _local\_deploy_hardbot2.py check
python _local\_deploy_hardbot2.py prepare-whisper
python _local\_deploy_hardbot2.py dry-run
python _local\_deploy_hardbot2.py deploy
```

`prepare-whisper`:

- атомарно копирует модель в `/opt/hardbot2/models/whisper`;
- проверяет размер и обязательные `model.bin`/`config.json`;
- делает timestamp-backup серверного `docker-compose.yml`;
- меняет только mount на
  `/opt/hardbot2/models/whisper:/models/whisper:ro`;
- проверяет `docker compose config --quiet`, но не перезапускает контейнер.

Обычный `deploy` теперь откажется продолжать, пока собственная модель и read-only
mount не подтверждены. Общий каталог Praxis не удаляется и не изменяется.

## 3. Разброс реестра по сотрудникам (пульт)

Пульт → раздел **Реестр** → карточка **Разброс по сотрудникам**:

1. **＋ Папка страны** — выбрать корни (напр. `…\Портфели отдела взыскания РТ`,
   `…\Портфели сотрудников УЗБ`), без хардкода путей.
2. **Мастер-реестр…** — выбрать `ОБЩИЙ РЕЕСТР {МЕСЯЦ}.xlsb`.
3. **Проверить совпадения** — превью (нашли папку / без папки / лишние), без записи.
4. **Разложить по папкам** — раскладка через Excel: `.xlsb` + списки «Статусы» +
   «Статистика» с формулами; `!Архив`/`_tech` игнорируются.

Требования на машине с пультом: установленный **Excel** (сам перенос делает он) и
**Python** с `xlwings`+`pandas`+`calamine` (движок `pult/razbros.py`, его зовёт пульт).
Сетевой диск с папками сотрудников должен быть примонтирован на этой машине.

## 4. Данные

Реальные ПД — **только локально**; на VPS — синтетика/демо (принцип подтверждён
операционным директором). Мастер-реестр и личные файлы сотрудников в git не попадают
(`.gitignore`: `*.xlsb/*.xlsx/*.db`, `Скрипт СНГ/Путь`, `Архив реестров`).
