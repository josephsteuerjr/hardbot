# Установка и обновление без интернета

Здесь лежит всё для случая, когда сервер стоит в закрытом контуре: интернета
нет ни у сервера, ни у машины, с которой его ставят.

Обычная установка (`deploy/units/*/install.sh`) собирает образы, а сборка ходит
в сеть дважды: за базовым образом Python и за пакетами `pip`. В закрытом
контуре это не «медленно», а «никогда»: установка не состоится, а обновление не
состоится тем более — его пришлось бы делать каждый раз.

Решение: образы собираются **один раз на машине с интернетом**, увозятся файлом
и заносятся в docker на месте. Ни pip, ни docker pull на закрытой машине не
вызываются вообще.

## Две команды на две машины

**Машина с интернетом** (любая, где есть docker и эти исходники):

```bash
cd deploy/offline
./bundle.sh                    # ядро + речь + модель small
```

Получится каталог `deploy/offline/out/hard-offline-<версия>-<дата>/`.
Скопировать его **целиком** на флешку.

**Закрытая машина** (туда же скопированы исходники системы):

```bash
cd /media/flash/hard-offline-...      # каталог с флешки
./load.sh
```

`load.sh` сверит контрольные суммы, занесёт образы в docker, разложит модель
речи и поставит отметку офлайн-режима. После этого — обычная установка:

```bash
cd /opt/hard/deploy/units/core && ./install.sh
cd /opt/hard/deploy/units/stt  && ./install.sh     # если нужен голос
```

Скрипты увидят отметку и ничего собирать не будут.

## Почему готовые образы, а не «привезём пакеты и соберём на месте»

| | Готовые образы | Сборка из колёс pip |
|---|---|---|
| Шагов на закрытой машине | одна команда | сборка каждой части, по-разному для каждой |
| Что может разойтись | ничего: образ — это уже собранная система | платформа (amd64/arm), версия python в базовом образе, отсутствие колеса под что-то, нехватка компилятора |
| Когда узнаешь о поломке | сразу, на `docker load`, с внятным текстом | посреди сборки, сообщением pip на английском |
| Размер пакета | больше (образ целиком) | меньше |

Мы платим размером флешки за то, что на той стороне нечему сломаться. Колёса в
пакет тоже кладутся (`./bundle.sh --with-wheels`) — на случай, если ИТ-служба
принципиально не берёт чужие собранные образы; тогда там же оказывается и
базовый образ python, за которым сборка иначе полезла бы в сеть. Это **запасной**
путь, см. `build-from-wheels.sh`.

## Что можно положить в пакет

```bash
./bundle.sh --with gps           # + маршрутизаторы OSRM и VROOM (единица gps)
./bundle.sh --with proxy         # + Caddy (профиль proxy единицы core)
./bundle.sh --model large-v3-turbo   # другая модель распознавания
./bundle.sh --no-model           # без модели: голос выключен
./bundle.sh --with-wheels        # + колёса pip и базовый образ python
./bundle.sh --out /media/flash   # писать сразу на флешку
```

Содержимое пакета:

| Что | Зачем |
|---|---|
| `images/*.tar` | образы: `hard-app`, `hard-stt`, при заказе — caddy, osrm, vroom, python |
| `model/models.tar` | модель распознавания речи. **Без неё голос в закрытом контуре не заработает**: контейнер речи при первом старте пойдёт на huggingface.co, не дойдёт и уйдёт в вечный перезапуск |
| `wheels/` | колёса pip (только при `--with-wheels`) |
| `SHA256SUMS`, `МАНИФЕСТ.txt` | контрольные суммы и слепок версий |
| `load.sh`, `verify.sh`, `README.md` | всё нужное для той стороны — прямо в пакете |

Каждый образ выгружается **с двумя именами**: `hard-app:latest` и
`hard-app:<версия>`. Первое нужно compose, второе — чтобы через полгода было
видно, что именно стоит, и чтобы можно было откатиться.

## Обновление без интернета

Ровно то же самое: собрать новый пакет на машине с интернетом, привезти,
`./load.sh`, затем в каталоге единицы `./update.sh`. Он сделает резервную копию
базы, увидит отметку офлайн и перезапустит контейнеры на уже загруженных
образах.

Откат на предыдущую версию, если новая не пошла (старый образ никуда не делся —
он остался под своим номером версии):

```bash
docker tag hard-app:1.4.0 hard-app:latest
cd deploy/units/core && docker compose up -d
```

## Что здесь лежит

| Файл | Кому |
|---|---|
| `bundle.sh` | тому, кто собирает пакет на машине с интернетом |
| `load.sh`, `verify.sh` | тому, кто ставит систему в закрытом контуре; оба кладутся и внутрь пакета |
| `build-from-wheels.sh` | запасной путь: сборка образов из колёс на закрытой машине |
| `mode.sh` | скриптам установки: подключается через `source` и отвечает на вопрос «собирать или нет». Руками не запускается |
| `OFFLINE` | отметка «здесь интернета нет», её ставит `load.sh`. Пока файл есть, `install.sh` и `update.sh` не собирают образы |

## Проверка

`./verify.sh` в каталоге пакета — сверка контрольных сумм, отдельно от всего
остального. Стоит запускать после копирования на флешку и после копирования с
неё: оборванное копирование выглядит как успешное, а всплывает потом, посреди
установки, ошибкой `unexpected EOF`.

## Типовые поломки

| Что видно | Что случилось | Что делать |
|---|---|---|
| `ИСПОРЧЕН images/hard-app_latest.tar` | файл не докопировался | скопировать пакет с флешки заново целиком |
| `docker load ... unexpected EOF` | то же самое, но обнаружено поздно | `./verify.sh`, затем скопировать заново |
| `install.sh` полез собирать образы | нет отметки `deploy/offline/OFFLINE` или скрипты старой версии | создать пустой файл `deploy/offline/OFFLINE`; либо поднять единицу напрямую: `docker compose up -d` |
| `ОШИБКА: на машине нет образов: …` | пакет заносили не на этой машине или не тот | `./load.sh` из пакета на **этой** машине |
| Контейнер речи перезапускается по кругу, в журнале — обращение к huggingface.co | модель не разложена или в `.env` указана другая | `tar -C deploy/units/stt/models -xf model/models.tar`, а в `.env` — `STT_MODEL` ровно из `model/ИМЯ-МОДЕЛИ.txt` |
| `No matching distribution found` при сборке из колёс | другая платформа или другая версия python | собирать образы на машине с интернетом и везти их, а не колёса |

## Чего в пакете нет

- **Дорожных графов OSRM** — это десятки гигабайт и отдельный рецепт
  (`deploy/geo/README.md`). Без них единица `gps` не нужна: система считает
  расстояния по прямой и работает.
- **Сертификатов HTTPS.** В закрытом контуре Let's Encrypt недоступен, значит
  профиль `proxy` бесполезен: нужен сертификат внутреннего удостоверяющего
  центра и свой обратный прокси. HTTPS обязателен — без него в приложении
  молча отключаются камера, геопозиция и работа без сети.
