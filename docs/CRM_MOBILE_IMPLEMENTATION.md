На телефоне файловый диалог заменён загрузкой файла/папки либо выбором разрешённого
корпоративного источника. Структура вложенных папок сохраняется. Результат скачивается
в браузере. Существующие долгие задания выполняются серверным Windows-исполнителем;
Excel создаётся и изменяется через xlwings, читается через calamine/xlwings.
Автозапуск Windows, DWM и выбор произвольного серверного пути в телефоне не имитируются.

## Интерфейс и сохранность

- Реальные бумажные токены, Golos Text / Zen Kurenaido и лицензии из десктопа.
  Нижнее меню, лист разделов, карточки портфеля и сводки показателей, формы снизу,
  внутренний скролл таблицы, раскрываемые инструменты и дополнительные действия.
- Safe area, клавиатура, портрет/альбом/планшет, системные назад/вперёд и восстановление
  открытой карточки после перезапуска. Обновление карточки сохраняет открытые действия.
- IndexedDB: неэкспортируемый AES-GCM ключ, зашифрованные значения и хэшированные адреса
  записей. CAS сохраняет конкурентные изменения вкладок; очередь и черновики связаны
  с исходной личностью и ролью. Миграция адреса раннего внутреннего кандидата атомарна.
- Сначала подтверждается локальная транзакция, затем показывается сохранение.
  Неизвестный ответ повторяет исходный `operation_id`. Файл документа отправляется
  до зависимого события; крупные/декодируемые фото подготавливаются локально.
- Активное время использует серверный якорь и доказанные выборки, отдельные префиксы
  вкладок. Фон, сон и длительный разрыв выборок не экстраполируются. Пересечения
  объединяет канонический сервер.
- Выгрузка сохраняет исходный экспорт, запрос записи, путь и SHA до ответа браузеру.
  Повторное чтение проверяет файл. Потерянное скачивание восстанавливается тем же ID
  из «Отправок» либо прежнего действия. Квитанция доставки отдельна от готовности
  файла: её ошибка остаётся видимой и не выдаётся за подтверждённую доставку.

## Серверная граница

`crm.mobile_server` — отдельный aiohttp BFF. Браузер получает непрозрачную HttpOnly,
SameSite=Strict cookie и CSRF; исходные токены и сессия CRM остаются зашифрованы на
сервере. Каждое действие перепроверяет канонический контекст и права. Отзыв или смена
личности закрывают BFF-вход, сохраняя исходную работу. Выход отзывает и исходную сессию.
Новые телефон, временный пароль и ожидание подтверждения имеют отдельные экраны.

`SharedBackend` допускает только HTTPS-службы `hard.rimborso.ru`. На primary новая
аудитория `crm-mobile` включается только `HARD_CRM_MOBILE=1`; роли и существующий
административный grant обязательны. Новый телефон Аналитика требует отдельного
подтверждения и не расходует разрешение на замену ПК. Геопозиция для входа не нужна.

Файлы выбираются через непрозрачные права, привязанные к владельцу. Произвольные
Windows/UNC/POSIX пути и выход из разрешённых каталогов не принимаются. Синтетика
имеет собственные БД, профили, файлы и отключённое отслеживание рабочих книг;
изменения инфраструктурных служб из неё запрещены. Native Excel выполняется отдельно
от канонического HTTP-процесса, чтобы его задержка не блокировала чтение CRM.

## Сборка и запуск

Из корня исходников:

```powershell
$env:HARD_CRM_MOBILE_OUT='C:/CRM-Mobile-Review/web'
node hard-desk/tools/build-mobile.mjs
npx --prefix hard-desk tsc --noEmit -p hard-desk
```

Проверочный стенд, из каталога `server`:

```powershell
python -X utf8 -m crm.mobile_server --demo-home C:/CRM-Mobile-Review/data --assets C:/CRM-Mobile-Review/web --receipt C:/CRM-Mobile-Review/runtime.json
```

Адрес выводится в консоль. Слушатель только loopback. Проверочная среда открывается
сразу выбором одной из пяти ролей без логина и пароля; после входа роли доступны
через «Подключение → Сменить роль». Реальные учётные записи ей не передаются.

С 17.11.2026 сборщик требует непустой `HARD_CRM_MOBILE_OUT`; использовать отдельный
абсолютный путь. Пустое значение останавливает сборку. Каталог `server/miniapp/crm`
может обслуживаться уже запущенным превью: не направлять туда проверочные сборки.
Параметр BFF `--assets` выбирает подготовленный пакет, независимо от каталога исходников.

Для общего контура предусмотрены `--home`, `--primary`, `--crm`,
`--session-key-file` (отдельный 32-байтный ключ с ограниченными правами),
`--public-origin https://hard.rimborso.ru`, `--native-executor`, `--source-root`
и `--prefix`. Служебные данные и ключи размещаются вне Git. Excel/Outlook-операции
требуют настроенного Windows-исполнителя и соответствующих прав исходного аккаунта.

## Проверки и выпуск

В кандидате проверены 32 серверных сценария, TypeScript, реальные браузерные
сценарии пяти ролей и native Excel. Отдельно проверены смена входа при открытом
выборе файла, сохранение исходного черновика/очереди и невозможность возродить
завершённую сессию поздним ответом. Все файловые продолжения удерживают исходного
владельца; поздний ответ прежнего входа не закрывает новый.

Фактические квитанции и изображения: ROOT `_local/crm-mobile-2026-11-16`.
Проверены канонические действия всех ролей, потеря ответа распределения/импорта/
скачивания, native Excel, устройства/сброс, автономная очередь/холодный SW/фото,
конкурентные вкладки, фактическая связка primary → shared CRM → BFF, обновление
истёкшей сессии и отзыв доступа. Проверки размеров и WebKit проводятся на внутренних
данных. Эмуляция WebKit не является приёмкой на физическом iPhone. Инцидент белого
экрана старой PWA112 остаётся отдельным, его исправление этим кандидатом не заявляется.

Рабочее включение требует существующих primary fence/проекций и адресной миграции
API/схемы/аудитории. Старый `server/web.py` целиком поверх свежего primary не выкладывать.
Превью и внутренние проверки не включают mixed writers на рабочих данных.
