# Работа Харда и Софта

Один договор может иметь двух разных ответственных. Хард определяется колонкой
ответственного Харда, Софт — колонкой ответственного Софта. Папка и книга нужны
для обмена с офисом; они не выдают доступ и не определяют роль в приложении.

| Шаг | Хард | Софт |
|---|---|---|
| Закрепление | Ответственный Хард в общем реестре | Ответственный Софт в общем реестре |
| Вход | Личная ссылка от руководителя/аналитика | Такая же выдача; новый сотрудник появляется в списке по Софт-закреплению |
| ПК | Чтение портфеля, комментарий, квитанции | Очередь звонков, результат и следующий контакт, комментарии, квитанции |
| Телефон | Завершение выезда, фото, гео | Запись звонка без требований к выезду |
| Дневная работа | Маршрут и план выездов | Сегодняшний/просроченный перезвон, дела без статуса или даты; весь портфель доступен отдельно |
| Человек с несколькими КД | Группа договоров своего Хард-владельца | Группа договоров своего Софт-владельца; чужой Софт-портфель закрыт |
| Новый комментарий | Текущий текст выезда и история | Новая заметка дописывается к накопленному тексту с автором и временем; журнал каждой попытки отдельный |
| Повтор | Повтор доставки того же op_id не создаёт второй факт | То же; повторная попытка дозвониться позднее сохраняется отдельным фактом |
| Без сети | Очередь телефона | Зашифрованная очередь ПК, неизменные op_id и время; видимые ошибки |
| Обогащение | Доказанный снимок выезда и день факта | Доказанный снимок звонка и день факта; будущая дата контакта не подтверждает свежесть |
| Конфликт с офисом | Снимок + доказанная доставка + эхо в книге | Те же принципы; доставка отдельно по каждой книге и профилю |
| Перевод Хард → Софт | Полный срез обоих профилей снимает прежнего владельца | Назначает нового Софт-владельца; история остаётся |
| СБ | Признаки выезда, гео, фотографии, контрольный обзвон | Журнал заявленных звонков; независимый факт телефонного соединения приложением не подтверждается |

Дополнительная активация ПК сотрудника не заменяет телефон. Повторное
подключение с действующим токеном этого ПК не расходует новый слот. Истёкшая
ссылка требует перевыпуска. Смена сотрудника при неотправленной очереди
блокируется; после отзыва входа очередь сохраняется для восстановления входа
той же личности. Старые очереди без известного ID нельзя безопасно приписать
новому пользователю — их нельзя очищать ради устранения ошибки.

Рабочий календарь и время карточек относятся к офисам UTC+5. Серверное время
приёма хранится отдельно в UTC. Поздняя доставка может означать отсутствие
сети; она не доказывает, что сотрудник задним числом выдумал результат.

С 07.10.2026 «Дата коммуникации» — день фактического звонка (UTC+5), который
сервер определяет по времени сохранения сотрудником. «Когда звонить снова»
хранится отдельно в приложении и управляет очередью; в колонку коммуникации
Excel будущая дата не попадает. «Общий результат» отражает последний результат
звонка или выезда. Вариант Софта «… sms» сохраняется в статусе Софта, а в общий
результат записывается соответствующее значение без суффикса.

Старые очереди принимаются с прежним именем поля перезвона. Для уже записанных
звонков сервер разделяет дату факта и перезвон при чтении снимка, не переписывая
журнал. Исправления попадут в личные книги при следующем штатном обогащении;
ручные изменения офиса проходят прежнее сравнение с историей доставки.

Карточка и форма звонка показывают «Оплаты из реестра»: дату и сумму последнего
платежа каждого договора с его валютой. Эти сведения обновляет импорт реестра.
Приложенный чек доступен отдельно и требует сверки с зачислением.

Дополнение 07.10, Desktop 2.0.5 / PWA80 / контракт v8: сотрудник может записать
новую оплату без фото, выбрав один договор, дату и сумму. Запись хранится с
автором и временем в журнале оплат; повтор доставки одного op_id не создаёт
вторую оплату. ПК и телефон сохраняют её в очередь при отсутствии сети.
В карточке отдельно видны текущие платежи из реестра и записанные сотрудником
оплаты. В Desktop 3.1.1 / PWA84 / контракте v10 дата и сумма последней ручной
оплаты записываются также в существующие колонки «Сумма последнего платежа»
и «Дата последнего платежа». Все записи с номером оплаты и КД остаются в
комментарии Софта при штатном обогащении; это работает также до первого звонка. Запись оплаты
не создаёт звонок или выезд и не считается подтверждённым зачислением реестра.

В форме можно выбрать «Оплачен» или «Оставить текущий статус». По умолчанию
статус сохраняется прежним. Выбранный результат и оплата сохраняются одной
операцией только для выбранного КД; при конфликте требуется обновить и сверить
карточку. Дата коммуникации не добавляется. Старые оплаты автоматически не
получают результат «Оплачен».

Для известного дефекта «Статистики сотрудника» обогащение исправляет только
точные формулы C2:C6, которые ошибочно суммируют колонку дат вместо
«Текущих платежей». Остальные формулы сохраняются. Изменения фиксируются в
резервной копии и квитанции доставки; ручная сумма не подменяет текущие платежи.

Комментарий текущего месяца Софта и прежний «Комментарий звонка» — разные
колонки. Метрика пропущенных прежних call-полей относится к старому офисному
блоку, а не к журналу Софта. Галочка замены текущих комментариев при импорте
относится к выездам. Приложение само не обнуляет Софт-комментарий первого числа.

При отсутствии рождения группировка требует совпадающего адреса, иначе
телефона; при отсутствии обоих договор остаётся отдельным. Телефоны и
дополнительные контакты реестра сохраняются. Софтник также может добавить новый
номер, имя контакта и пояснение в форме звонка: они накапливаются и через штатное
обогащение попадают в «Доп. Адрес/Доп.Номер». Приложение не может восстановить
отсутствующий номер по ФИО.

## Первый рабочий день

Локальная версия по требованиям встречи 08.10.2026: Desktop 2.0.6 / PWA81 /
контракт v9. В очереди «Сегодня» и «Все» добавлен фильтр по контрагенту.
Группа человека с несколькими контрагентами остаётся целой: фильтр выбирает
человека, а не скрывает часть его договоров.

Статус «Встреча в офисе» и общая дата «Дата встречи/Дата перезвона» записывают
плановый контакт. Дата коммуникации по-прежнему является днём факта звонка.
При встрече форма требует дату; обычный перезвон имеет ту же плановую дату.
Экспорт использует новое название колонки, а импорт и обмен принимают также
старое «Дата встречи». Срок встречи/перезвона не ограничен тремя днями.

Обещание Софта — от дня звонка до дня звонка + 3 календарных дня включительно
(UTC+5). Настройка предела выездников этот срок не меняет. Для нового PTP форма
собирает дату и сумму с точностью до копеек. Старые очереди совместимы; сервер
отклоняет неверную дату отдельным полем, сохраняя сам звонок.

Руководитель выбирает день или «За всё время». В Excel добавлены листы
«Софт · операции» по предоставленному шаблону и «Софт · обещания» для проверки
KP. Определения и ограничения истории: [Отчётность Софта](soft-reporting.md).

Перед выдачей руководитель проверяет назначение и выдаёт личную ссылку через
«Вход команды». Сотрудник копирует всю готовую папку приложения на свой ПК,
входит, проверяет свой портфель и открывает карточку. Для обучения использовать
тестовые данные или разбор без сохранения; фиктивный звонок в рабочем журнале
создавать нельзя.

После настоящего звонка записать статус, только новую заметку, следующий
контакт и обещание, если оно дано. Проверить, что результат принят сервером,
а не только ждёт отправки. В случае ошибки закрепления не удалять очередь
до проверки руководителем. Квитанцию прикладывать с суммой и датой из снимка;
она требует сверки с фактическим зачислением.

Офисный цикл: сервер → обогащение личной книги → перенос личных книг в общий
реестр → отдельный предпросмотр и импорт опубликованного общего реестра.
Обновление приложения не запускает этот цикл. Перед полной раздачей обоих
профилей предпросмотр включает прежних владельцев, а не только новых.

При обновлении достаточно заменить полный комплект и полностью выйти через
значок у часов, затем открыть новую программу. Закрытие окна только сворачивает
её. Данные приложения и неотправленные очереди вручную не удалять.
