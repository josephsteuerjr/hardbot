# Если не работает

Симптом — причина — что сделать. Всё перечисленное здесь происходило на самом
деле, это не список воображаемых бед.

Главное правило: **не ждать.** Если контейнер перезапускается по кругу, он не
«ещё грузится». Причина всегда в последних строках журнала:

```bash
cd /opt/hard/deploy/units/core && sudo docker compose logs --tail=50 app
```

---

## При установке

| Что видно | Что это значит | Что сделать |
|---|---|---|
| `bash: ./install.sh: Permission denied` | скрипты приехали без права запуска — так бывает после копирования с Windows или распаковки архива. `sudo` не поможет: дело не в пользователе, а в файле | `sudo chmod +x /opt/hard/deploy/*.sh /opt/hard/deploy/units/*/*.sh` |
| «нужен Docker Compose v2 (команда `docker compose`)» | стоит старый `docker-compose` версии 1 либо движок без плагина | `sudo apt install docker-compose-plugin` |
| Сборка падает, в журнале `CERTIFICATE_VERIFY_FAILED` или `x509` | исходящий трафик машины вскрывается средством инспекции, и его корневой сертификат системе неизвестен | либо ИТ-служба ставит свой корневой сертификат в систему и в docker, либо ставим привезёнными образами: `cd 1-образы && sudo ./load.sh --deploy /opt/hard/deploy` |
| `failed to resolve reference` при запуске после офлайн-установки | образы заносили не на этой машине или не те | повторить `./load.sh` из пакета **на этой** машине |
| `network hard-net declared as external, but could not be found` | запустили `docker compose` руками, минуя `install.sh` | `docker network create hard-net && docker volume create hard-stt-run` |
| Порт занят | на машине уже что-то слушает 8080 | сменить `APP_PORT` в `.env` ядра и `./update.sh` |
| Контейнер по кругу, в журнале `unable to open database file` | на системах с SELinux (RHEL, Rocky, Astra) контейнеру закрыт доступ к каталогу данных | добавить `:Z` к тому `./data:/data` в `docker-compose.yml` — или ставить на Ubuntu, как в требованиях |
| «служба hard-ops-agent не запустилась» | путь установки содержит пробелы или кириллицу, либо ставили не от root | перенести в `/opt/hard`, переустановить ядро от root |

## Приложение поставилось, но ведёт себя странно

| Что видно | Что это значит | Что сделать |
|---|---|---|
| **Приложение открывается, но нет камеры, геопозиции и работы без сети** | нет HTTPS. Самая частая и самая тихая поломка: страница выглядит рабочей | сертификат на публичный адрес, см. шаг 7 «Начни отсюда» |
| Карта серая, рисуется медленно, подгружается из интернета | в `data/` нет файла `basemap.pmtiles`, приложение ушло на запасную интернет-подложку | скопировать карту из `3-ресурсы`, перезапустить ядро |
| Голос не появляется | в `.env` ядра `VOICE_BACKEND` не равен `stt`, либо единица `stt` не поставлена | поправить и `./update.sh`; проверить `cd units/stt && ./doctor.sh` |
| Речь по кругу перезапускается, в журнале «модели нет» | образ собран без модели | пересобрать `stt` из привезённого образа, а не из исходников |
| Фотографии не доходят, у сотрудника «снимок потерян» | между телефоном и сервером стоит фильтр (WAF, ограничитель частоты), который отвечает отказом. Приложение считает такой ответ окончательным и снимок удаляет | убрать фильтр с пути загрузки фотографий |
| Порядок объезда «по прямой» | единица gps не поставлена или в `.env` ядра пустые адреса маршрутизаторов | шаг 6 |
| Сводка руководителю показывает нули у всех | после переезда люди получили новые идентификаторы: базу снимали без переноса привязок | снимать архив с ключом `--with-people` |

## Снаружи не открывается

| Что видно | Что это значит | Что сделать |
|---|---|---|
| Из офиса открывается, с телефона по мобильному интернету — нет | публикации наружу нет; работает только внутренняя сеть | это к ИТ-службе, `ТРЕБОВАНИЯ-ИТ.md` |
| `./doctor.sh` говорит «замечаний нет», а снаружи не открывается | **так и задумано, и это ловушка**: доктор проверяет приложение по `127.0.0.1` и смотрит на `MINIAPP_URL` только как на строку. Что адрес кому-то отвечает, не проверяет никто | проверять руками с телефона, а не по выводу доктора |
| Ссылка сотруднику ведёт в никуда | `MINIAPP_URL` не совпадает с фактическим адресом, либо после правки не перезапустили ядро | поправить `.env`, `./update.sh` |
| Сертификат просрочен или не выпускается | встроенный Caddy не может получить сертификат: закрыт входящий 80, либо запись в DNS не указывает на эту машину | `sudo docker compose logs caddy` и к ИТ-службе |

## Когда ничего не помогает

Снять состояние целиком и передать тому, кто делал систему:

```bash
cd /opt/hard/deploy && ./doctor.sh > /tmp/состояние.txt 2>&1
cd units/core && sudo docker compose logs --tail=200 app >> /tmp/состояние.txt 2>&1
```

В этом файле нет ни фамилий должников, ни фотографий — только техническое
состояние машины. Секреты из `.env` в него тоже не попадают.

Вернуться на вчерашнее состояние базы, если сегодняшнее испорчено:

```bash
cd /opt/hard/deploy/units/core && sudo ./restore.sh backups/<каталог копии>
```

Текущая база при этом не удаляется — она откладывается рядом под именем
`hardbot.db.before-restore-*`, и тем же скриптом можно вернуться на неё обратно.
