# Caddy с исправленным Go

Образ `hard-caddy:2.11.7-go1.26.10-20261026` используется в compose с 26.10.2026.
Официальный бинарник Caddy 2.11.7 был собран на Go 1.26.8. Здесь тот же выпуск
пересобран на Go 1.26.10 с исправлением CVE-2026-111943 и предыдущими исправлениями
ветки Go 1.26. Версии 135 модулей Caddy и 147 зависимостей сохранены.

Для Linux amd64 образ можно собрать из корня проекта:

```sh
docker build -t hard-caddy:2.11.7-go1.26.10-20261026 deploy/caddy-go
docker run --rm --entrypoint caddy hard-caddy:2.11.7-go1.26.10-20261026 build-info
```

Первые стадии требуют интернета. Архивы официального SDK Go и исходников Caddy
проверяются по закреплённым SHA256/SHA512, сама компиляция выполняется без сети
из vendored-зависимостей выпуска. Рабочая выкладка была собрана теми же командами
из предварительно проверенных архивов и точного исходного runtime image.
Полная повторная сборка этого многостадийного Dockerfile отдельно не выполнялась.

Это **локальный образ**, он не опубликован в Docker Hub. Для офлайн-пакета нужно
включать его через `docker save` и загружать через `docker load`; выполнять pull
этого имени из Docker Hub не следует. Перед пересозданием контейнеров проверить,
что локальный тег существует. Не заменять его обычным `caddy:2.11.7`: исходный
официальный бинарник не содержит требуемого исправления Go.

Для следующих обновлений сверять `caddy build-info`, версии модулей, фактические
Caddyfiles, environment и весь VPN-блок парсеров. До смены образа сохранять
конфиги и TLS-состояние. При откате Caddy не возвращать старую прикладную БД.

Источники: [исправление Go](https://github.com/golang/go/issues/82345),
[выпуск Caddy](https://github.com/caddyserver/caddy/releases/tag/v2.11.7).
Caddy распространяется под Apache-2.0, Go — под BSD-3-Clause; исходные лицензии
находятся в официальных архивах и сохраняются вместе с ними.
