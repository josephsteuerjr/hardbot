# Выезды — установка на сервер

Инструкция для системного администратора. Установка занимает около получаса:
десять минут на сборку образов, остальное — HTTPS и заполнение настроек.

Стек — один `docker compose` в этой папке:

| Сервис | Что делает | Память |
|---|---|---|
| `app` | приложение сотрудника (PWA), административный API для пульта, Telegram-бот (необязателен) | ≈ 0,3 ГБ, пики выше при загрузке реестра |
| `stt` | распознавание голосовых комментариев; свой контейнер, наружу не ходит | small ≈ 0,7 ГБ, medium ≈ 1,8 ГБ, large-v3 ≈ 3,5 ГБ |
| `caddy` (профиль `proxy`) | HTTPS «из коробки», если нет своего nginx | ≈ 0,05 ГБ |
| `osrm-*` (профиль `routing`) | порядок объезда по реальным дорогам | ≈ 0,5–1 ГБ на страну |

Всё состояние — в `data/` (база, фотографии, выгрузки) и `models/` (модели
речи). Пересборка образов их не трогает.

---

## Что нужно

| | |
|---|---|
| Сервер | 2–4 ядра, **4 ГБ памяти** с голосом на модели `small` (8 ГБ — с `medium` или маршрутами), от 100 ГБ диска |
| Система | любой Linux с Docker Engine и Docker Compose v2 (`docker compose version`) |
| Сеть | доступ в интернет при установке (образы, модель речи ≈ 460 МБ); дальше — только для Telegram, если он включён |
| Домен | один поддомен компании с сертификатом — или открытые порты 80/443 для встроенного Caddy |

Диск расходуется в основном на фотографии — около 250 КБ на снимок. При
девяти сотрудниках это порядка 4–5 ГБ в год.

---

## HTTPS обязателен

**Это единственное требование, ошибка в котором ломает всё.**

Приложение сотрудника — это PWA. Три его ключевых способности браузер выдаёт
только на защищённом соединении:

- работа без интернета (данные копятся на телефоне и уходят при связи);
- доступ к камере — фотографии вручения;
- доступ к геопозиции — подтверждение, что сотрудник был на адресе.

По `http://` браузер отключит всё три молча: приложение откроется и будет
выглядеть рабочим, но фото и геолокация работать не будут, а без сети оно
не запустится вообще.

Поэтому перед сервисом ставится обратный прокси с сертификатом — nginx, Caddy,
Traefik, что принято в компании. Сам сервис слушает только `127.0.0.1:8080`
(порт меняется через `APP_PORT` в `.env`).

Пример для nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name vyezdy.company.ru;

    ssl_certificate     /etc/ssl/company/fullchain.pem;
    ssl_certificate_key /etc/ssl/company/privkey.pem;

    client_max_body_size 30m;          # фотографии

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;           # загрузка фото по слабой мобильной сети
    }
}
```

**Если своего прокси нет** — включите встроенный: в `.env` задайте
`DOMAIN=vyezdy.company.ru` и `COMPOSE_PROFILES=proxy`, направьте DNS-запись
домена на сервер, откройте порты 80 и 443 и выполните `./update.sh`. Caddy сам
получит сертификат Let's Encrypt и будет его продлевать.

## Установка одной командой

```bash
# 1. Распаковать пакет; рядом должны лежать hardbot/, stt/ и deploy/
cd deploy

# 2. Установить: проверит Docker, создаст .env и секреты, соберёт, запустит,
#    дождётся готовности обоих сервисов
./install.sh

# 3. Заполнить настройки и применить
nano .env          # ADMIN_ID, MINIAPP_URL; BOT_TOKEN — если нужен Telegram
./update.sh

# 4. Убедиться
./doctor.sh
```

`install.sh` можно запускать повторно — существующие `.env`, секреты и данные
он не трогает. Он создаёт:

- `.env` из `.env.example` с уже сгенерированным `ADMIN_API_KEY` (нужен пульту);
- `secrets/stt.token` — токен, по которому приложение обращается к службе речи;
- `data/`, `models/`, `backups/`.

Первый запуск службы речи скачивает модель (`small` ≈ 460 МБ); пока идёт
загрузка, `docker compose ps` показывает `stt` как `starting` — это нормально,
приложение уже работает, голос появится через несколько минут.

## Проверка после установки

1. `./doctor.sh` — оба сервиса `healthy`, HTTP 200, распознавание «готова».
2. Открыть `https://ваш-домен/` в браузере — должна открыться страница входа.
3. Написать боту в Telegram слово `ссылка` — придёт персональная ссылка входа.
   (Без Telegram ссылки входа сейчас выдаёт только бот — см. раздел «Telegram».)
4. Открыть её **на телефоне**, добавить приложение на экран.
5. Открыть любую карточку, сделать фотографию. Она должна уйти за 1–3 секунды.
6. Включить на телефоне авиарежим, заполнить карточку, выключить авиарежим —
   данные должны уйти сами.
7. Нажать микрофон в комментарии, надиктовать фразу — текст должен появиться.

Шестой пункт — главный. Если он не работает, почти наверняка дело в HTTPS.

## Обновление

```bash
cd deploy
# заменить содержимое ../hardbot и ../stt новой версией (deploy/ — тоже, кроме .env и secrets/)
./update.sh
```

`update.sh` сам снимает копию базы, пересобирает образы, перезапускает
сервисы и ждёт их готовности. Данные при этом не затрагиваются: они лежат в
`data/`, отдельно от образа. Если что-то пошло не так — `./restore.sh` на
только что снятую копию.

Тем же `./update.sh` применяются правки `.env`.

---

## Резервные копии

```bash
./backup.sh            # база + фотографии
./backup.sh --db-only  # только база, секунды
```

База копируется онлайн-бэкапом SQLite изнутри контейнера — обычное копирование
файла работающей базы может дать несогласованный снимок. Копии базы лежат в
`backups/<дата-время>/hardbot.db`, старые удаляются (хранится `BACKUP_KEEP`
последних, по умолчанию 14). Фотографии не меняются после записи, поэтому
`backups/photos/` — одно зеркало, в которое досылается только новое.

Рекомендуемый режим — ежедневно, cron от root:

```
15 3 * * * cd /opt/vyezdy/deploy && ./backup.sh >> backups/backup.log 2>&1
```

Папку `backups/` копируйте на другой носитель средствами компании.

Восстановление:

```bash
./restore.sh backups/20260902T031500            # только база
./restore.sh backups/20260902T031500 --photos   # база и фотографии
```

Скрипт остановит приложение, отложит текущую базу в
`data/hardbot.db.before-restore-*`, подменит файлы и запустит приложение снова.

## Telegram: включить или выключить

Telegram — необязательный канал. Пустой `BOT_TOKEN` в `.env` — сервер работает
как приложение: карточки, фото, геоконтроль, пульт. Не работают только пуши
руководителям и вечерние сводки; каждый пропуск записывается в журнал доставки,
который виден в пульте.

- **Включить**: вписать в `.env` токен от @BotFather (`BOT_TOKEN=…`) и
  `./update.sh`. В журнале появится «Бот запущен».
- **Выключить**: очистить `BOT_TOKEN=` и `./update.sh`. В журнале — «Telegram
  отключён: BOT_TOKEN пуст, работает только приложение».

Один токен — один сервер. Два экземпляра с одним токеном ломают друг друга
(Telegram отвечает 409).

Ограничение текущей версии: персональную ссылку входа сотруднику выдаёт бот
(команда «ссылка»). Уже вошедшие телефоны работают без Telegram (вход живёт 30
дней и продлевается при использовании), но подключить новый телефон без бота
пока нельзя.

## Голос: включить или выключить

- `VOICE_BACKEND=stt` (по умолчанию) — голосовые комментарии включены,
  контейнер `stt` работает.
- `VOICE_BACKEND=off` — выключено; `install.sh`/`update.sh` не запускают `stt`
  и память не расходуется. Сотрудники вводят текст руками.

Модель — `STT_MODEL` в `.env`: `small` (по умолчанию, ≈ 0,7 ГБ, хватает для
коротких надиктовок), `medium` (≈ 1,8 ГБ, лучше на шуме), `large-v3`
(≈ 3,5 ГБ, лучшее качество, в 3–4 раза медленнее). После смены — `./update.sh`;
новая модель скачается в `models/`, образ пересобирать не нужно.

Служба речи не имеет сетевого порта: приложение обращается к ней через
Unix-сокет в общем томе, с токеном из `secrets/stt.token`. Аудио живёт в
памяти контейнера только на время распознавания и в журнал не попадает.
Подробности — `../stt/README.md`.

## Маршрутизация по дорогам

Необязательна: без неё порядок объезда считается упрощённо, система работает
полностью. Требует подготовленного графа дорог на страну — рецепт и опыт
боевой машины в `geo/README.md`. Когда графы лежат в `osrm/uz/`, `osrm/tj/`:

```
COMPOSE_PROFILES=routing
OSRM_URL_UZ=http://osrm-uz:5000
OSRM_URL_TJ=http://osrm-tj:5000
```

и `./update.sh`. Считайте 0,5–1 ГБ памяти на страну.

## Чего не делать

**Не ставить лимит памяти контейнеру `app`.** При обычной работе сервис
занимает около 300 МБ, но при загрузке большого реестра кратковременно берёт
заметно больше. С потолком 768 МБ контейнер убивало нехваткой памяти пять раз
подряд. Если ограничение требуется политикой — не ниже 2 ГБ. Для `stt` лимит
допустим (`STT_MEM_LIMIT`), но с запасом к таблице памяти.

**Не публиковать порт приложения наружу.** Сервис рассчитан на работу за
обратным прокси и сам сертификат не обслуживает. `APP_PORT` слушает только
`127.0.0.1`.

**Не хранить `.env` и `secrets/` в системе контроля версий** и не
пересылать их почтой. В них ключ пульта, токен бота, токен службы речи.

**Не запускать два сервера с одним `BOT_TOKEN`.**

**Не копировать `data/hardbot.db` обычным `cp` у работающего сервера** —
только `./backup.sh`.

**Не редактировать `docker-compose.yml` ради настроек** — всё, что нужно
менять, вынесено в `.env`.

## Если что-то не работает

Первым делом — `./doctor.sh`: он покажет состояние контейнеров, ответ
приложения, службу речи, диск, память и последние ошибки.

| Симптом | Где смотреть |
|---|---|
| `app` не становится healthy | `docker compose logs app` — обычно ошибка в `.env` |
| `stt` долго `starting` | скачивается модель; `docker compose logs stt` покажет прогресс. Дольше 15 минут — нет доступа в интернет из контейнера |
| Голос: «временно недоступен» | `./doctor.sh` → служба речи; `secrets/stt.token` должен быть файлом с правами 0640 |
| Страница открывается, фото не отправляются | HTTPS и `client_max_body_size` в прокси |
| Приложение не работает без сети | почти всегда HTTPS: по http браузер отключает автономный режим |
| Сотрудник не получает ссылку | он не привязан; привязка подтверждается владельцем при `BIND_APPROVAL=1` |
| Пульт не подключается | `ADMIN_API_KEY` из `.env` и адрес `https://…` без завершающего `/` |
| Кончается место | `du -sh data/photos` — основной рост здесь; `backups/` можно переносить |

Журнал: `docker compose logs --since=1h app`, `docker compose logs --since=1h stt`.
В журналах нет адресов должников, координат и содержимого голосовых записей.
