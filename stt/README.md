# Служба распознавания речи

Свой контейнер для голосовых комментариев выездника: сотрудник надиктовывает
текст в приложении, сервер отдаёт запись сюда, назад приходит текст. Внутри —
[faster-whisper](https://github.com/SYSTRAN/faster-whisper) на CPU.

Служба **не имеет TCP-порта**. Она слушает только Unix-сокет в общем томе,
требует Bearer-токен из файла и обрабатывает один запрос за раз. В журнал не
попадают ни аудио, ни имена файлов, ни распознанный текст — только код ответа,
язык и длительность.

**И в интернет она не ходит.** Модель запечена в образ, скачивание выключено на
двух уровнях сразу. Это не про безопасность, а про то, чтобы служба поднималась
на объекте, где интернета нет, доступ к huggingface.co закрыт или канал такой,
что полтора гигабайта идут полдня.

## Модель едет в поставке

Модель готовит `tools/prepare_stt_model.py` — один раз, на машине сборки:

```bash
python tools/prepare_stt_model.py            # в stt/model появится модель
python tools/prepare_stt_model.py --verify   # проверить, что довезена целиком
```

Скрипту не нужен ни ctranslate2 на машине, ни ключи: если своего ctranslate2
нет, он делает всё внутри образа службы речи. Дальше `docker compose build stt`
запекает `stt/model` в образ по пути `/opt/hard/stt-model`.

Три вещи, которые стоит знать про этот путь и эту модель.

**Почему не `/models`.** На `/models` compose вешает том под кэш скачивания, а
том перекрывает всё, что лежало в образе по этому пути. Модель, запечённая в
`/models`, просто исчезла бы при первом же запуске, и понять почему было бы
нельзя. `/opt/hard/stt-model` никто не монтирует.

**Почему int8 на диске, а не float16.** faster-whisper всё равно квантует веса
в int8 при загрузке — но делает это каждый раз заново, в памяти. Мы делаем это
один раз при подготовке. Замерено на одной и той же модели: из float16 —
загрузка 28 с и пик 1,64 ГБ, из готового int8 — загрузка 8 с и пик 1,24 ГБ,
файл 0,82 ГБ вместо 1,62 ГБ. Текст распознавания совпадает дословно.

**Почему `STT_MODEL` осталась именем, а не путём.** В `.env` пишут
`STT_MODEL=large-v3-turbo`, как и раньше — про путь внутри образа знать не надо.
Служба разбирается сама, по манифесту `hard-model.json`, и порядок такой:

1. имя совпало с запечённой моделью — берёт её из образа;
2. не совпало — ищет по имени в кэше `/models` (вдруг её туда положили заранее);
3. не нашлась и там, а качать запрещено — **берёт запечённую и громко пишет об
   этом в журнал**;
4. запечённой нет вовсе — останавливается и говорит, что делать.

Третий пункт стоит объяснить. Имя модели живёт в `.env`, а сама модель — в
образе, и разъехаться им проще простого: в `.env` остался старый `STT_MODEL`, а
образ пересобрали с другой моделью. Отказ в этом месте означает «голоса нет
совсем» и разбирательство на объекте. Подмена означает «голос работает, но не
той моделью» и строчку в журнале, которая прямо говорит, что произошло и как
это поправить. Подмена срабатывает только последней — она не перебивает ни явно
указанный путь, ни модель, заранее положенную в `/models`.

Пустой `stt/model` — не ошибка сборки: образ соберётся, но служба откажется
стартовать со словами «в образе модели нет». Это лучше, чем молча уйти качать
полтора гигабайта.

Если модель не загрузилась и подставить нечего, служба **останавливается**, а не
висит «прогревающейся». Работать без модели она всё равно не может, а ядро
отсутствие речи переживает — сотрудник вводит текст руками. Зато причина видна
в первую же минуту, а не через пятнадцать.

## Контракт

Все ответы — JSON. Схемы `praxis.stt.*` — это версия проводного формата, под
которую написан клиент `server/stt_client.py`; менять их нельзя без смены
клиента.

| Запрос | Ответ |
|---|---|
| `GET /healthz` (Bearer) | `200 {"schema":"praxis.stt.health.v1","status":"ready","ready":true,"busy":false}`; пока модель грузится — `503` с `"status":"warming"` |
| `POST /v1/transcriptions` (Bearer, multipart: `audio` — байты, `language` — `ru`/`uz`/`auto`) | `200 {"schema":"praxis.stt.v1","request_id":"…","text":"…","language":"ru"}` |

Ошибки: `{"schema":"praxis.stt.error.v1","request_id":"…","error":{"code":"…","message":"…"}}`

| Статус | `code` | Когда |
|---|---|---|
| 401 | `unauthorized` | нет или неверный токен (заголовок `WWW-Authenticate: Bearer`) |
| 400 | `invalid_multipart`, `missing_audio`, `empty_audio`, `missing_language`, `invalid_language`, `unexpected_field`, `duplicate_*`, `field_too_large` | форма собрана неправильно |
| 408 | `upload_timeout` | тело не дошло за `STT_UPLOAD_TIMEOUT` секунд |
| 413 | `audio_too_large` | больше `STT_MAX_BYTES` (потолок 15 MiB) |
| 415 | `unsupported_media_type` | не `multipart/form-data` |
| 422 | `transcription_failed` | файл не декодируется или модель не справилась |
| 429 | `busy` (`Retry-After: 2`) | модель занята другим запросом |
| 429 | `rate_limited` (`Retry-After: N`) | превышен лимит `STT_RATE_PER_MINUTE`/`STT_BURST` |
| 503 | `warming` (`Retry-After: 2`) | модель ещё грузится |
| 500 | `internal_error` | неожиданный сбой; подробности только в журнале, без данных |

## Настройки (env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `STT_MODEL` | `large-v3-turbo` | имя модели или путь к каталогу с ней |
| `STT_BAKED_MODEL_DIR` | `/opt/hard/stt-model` | где в образе лежит запечённая модель |
| `STT_ALLOW_DOWNLOAD` | `0` | `1` разрешает качать модель с huggingface.co при старте |
| `STT_COMPUTE_TYPE` | `int8` | точность вычислений; `int8` — самый экономный на CPU |
| `STT_DEVICE` | `cpu` | `cpu`; `cuda` только при наличии GPU и соответствующего образа |
| `STT_THREADS` | `0` | потоков CPU на распознавание; `0` = по числу ядер, но не больше 4 |
| `STT_BEAM_SIZE` | `5` | ширина поиска; на turbo почти не влияет на время (см. ниже) |
| `STT_MODELS_DIR` | `/models` | кэш скачивания (том); при запечённой модели не используется |
| `STT_SOCKET` | `/run/stt/stt.sock` | путь сокета в общем томе (права 0660) |
| `STT_TOKEN_FILE` | `/run/stt/stt.token` | файл с токеном: 32+ печатных ASCII-символов, не читаемый всеми |
| `STT_TOKEN_INSECURE_OK` | `0` | аварийно отключает проверку прав на файле токена (см. ниже) |
| `STT_MAX_BYTES` | `15728640` | лимит аудио (не больше 15 MiB — столько же режет клиент) |
| `STT_RATE_PER_MINUTE` | `6` | запросов в минуту после исчерпания запаса |
| `STT_BURST` | `2` | запас запросов «подряд» |
| `STT_UPLOAD_TIMEOUT` | `30` | секунд на приём тела |
| `STT_TEMP_DIR` | `/tmp/stt` | куда класть аудио на время распознавания; в compose это tmpfs |

Загрузка модели при старте идёт в фоне: сокет отвечает сразу, но `/healthz`
отдаёт `503 warming`, а распознавание — `503` с `Retry-After`, пока модель не
готова. Приложение показывает выезднику «голос временно недоступен» и оставляет
ручной ввод.

## Память и время

Замерено 2026-09-10 на Docker Desktop, 4 ядра контейнеру, запись
`_local/praxis-stt-canary-ru.mp3` длиной 8,3 с. Память — пик RSS процесса
(`VmHWM`), то есть максимум за всё время, а не то, что показывает `docker stats`
в спокойную минуту.

| Модель | Пик памяти | На диске | Загрузка | Запись 8,3 с |
|---|---|---|---|---|
| `large-v3-turbo` int8 (запечена) | 1,20–1,24 ГБ | 0,82 ГБ | 3–10 с | 18–20 с |
| `large-v3-turbo` float16 (если положить неквантованную) | 1,64 ГБ | 1,62 ГБ | 28 с | те же 18–20 с |
| `small` int8 (замер 2026-09-02) | 0,92 ГБ | 0,46 ГБ | ≈ 5 с | ≈ 5 с |

`STT_MEM_LIMIT` для turbo — **2000m**. Тесный лимит здесь, вопреки ожиданию,
не убивает контейнер, а замедляет его: бо́льшая часть тех 1,2 ГБ — это сам файл
модели, отображённый в память, и ядро вытесняет его, когда упирается в лимит,
а потом читает с диска снова. Замерено на одной и той же записи: 2000m — 19 с,
1500m — 26 с, 900m — 35 с, и ни разу OOM. То есть «служба стала тупить» — это
скорее про лимит памяти, чем про процессор.

Две вещи, которые видно из замеров и которые экономят время на настройке.

**Ширина луча почти ничего не меняет** (17,8 с при `STT_BEAM_SIZE=1` против
18,6 с при 5). У turbo 32 слоя энкодера и всего 4 слоя декодера: почти всё время
уходит в энкодер, а лучом настраивается декодер. Крутить `STT_BEAM_SIZE` ради
скорости бессмысленно — качество потеряете, секунд не выиграете.

**Длина записи почти ничего не меняет** — по той же причине: энкодер всегда
обрабатывает окно в 30 секунд целиком, хоть в нём две секунды речи, хоть
двадцать пять. Двадцать секунд на короткую надиктовку — это не «тормозит», это
цена turbo. Нужно быстрее — только `small`, и это заметная потеря качества на
шумной записи с улицы.

**Больше потоков не помогает**: 8 потоков оказались не быстрее 4 (а с узким
лучом даже медленнее — потоки начинают мешать друг другу). Поэтому `STT_THREADS=0`
и берёт не больше четырёх.

## Проверка прав на файле токена

Служба требует, чтобы файл токена не читался всеми, и это остаётся. Но проверка
устроена не «посмотреть режим и отказаться», а «попробовать сузить права и
посмотреть, что вышло» — потому что не всякая файловая система права вообще
хранит. Bind-mount с Windows показывает у любого файла `0777` просто потому, что
взять права ему неоткуда, и служба, доверявшая этому числу, уходила в вечный
цикл перезапусков с советом сделать `chmod 640`, который ничего не менял.

Что делает служба, увидев «читается всеми»:

| Что вышло | Вывод | Что делает |
|---|---|---|
| `chmod 640` сработал | права были настоящие, теперь файл закрыт | работает, в журнале предупреждение |
| `chmod` не сработал (только чтение, чужой владелец) | права настоящие, починить нельзя | останавливается |
| `chmod` «удался», но режим не изменился | файловая система права не хранит | работает, в журнале громкое предупреждение |

`STT_TOKEN_INSECURE_OK=1` оставлен на непредусмотренный четвёртый случай:
проверка выключается целиком и при каждом старте пишет об этом в журнал строкой
уровня ERROR. Ставить его «чтобы заработало» не надо — сперва посмотрите, что
именно написано в журнале.

## Проверка вручную

Изнутри контейнера (так работает healthcheck):

```bash
docker compose exec stt python server.py --check      # «готова» / «не готова: warming»
```

Через сокет из контейнера приложения:

```bash
docker compose exec app python -c "
import asyncio, stt_client
c = stt_client.STTClient(token_file='/run/stt/stt.token', unix_socket='/run/stt/stt.sock')
print(asyncio.run(c.health()))
"
```

Что запечено в образ:

```bash
docker compose exec stt cat /opt/hard/stt-model/hard-model.json
```

## Тесты

`tests/test_stt_service.py` гоняет всю HTTP-часть на подменном распознавателе
без модели (секунды, без сети). Тест с настоящей моделью запускается только
при наличии `faster-whisper`, каталога моделей в `STT_MODELS_DIR` и
синтетической записи `_local/praxis-stt-canary-ru.mp3`; иначе пропускается.
