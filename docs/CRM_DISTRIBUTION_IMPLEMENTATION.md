# Внутренний кандидат Руководителя, 14.11.2026

Основание: `CRM_MANAGER_SCOPE.md` / `CRM_MANAGER_NIGHT_PLAN.md`.
Версия кандидата: **3.3.0-manager.1**. Это изолированный внутренний срез;
включение распределения в рабочем смешанном контуре не подготовлено.

## Модель и команды

- Схема PostgreSQL/SQLite **5**, аддитивная миграция от 4. Исторические интервалы
  `crm_assignments` сохранены; `crm_assignment_heads` задаёт одного эффективного
  ответственного или явное снятие. Пересекающиеся старые назначения дают состояние
  сверки и не превращаются в два эффективных разрешения.
- Управляемый портфель — явные `crm_managed_contracts` (команда × договор × работа)
  и `crm_distribution_managers` (личность руководителя × команда × работа), плюс
  актуальное полномочие `assign`. Общий просмотр и название роли не создают область.
- `assignment-preview` фиксирует состав, версии, действие, цель, автора и срок.
  `assignment-commit` принимает только этот preview и `operation_id`; hash тела,
  квитанция и история защищают replay/потерю ACK/другой payload.
- До 200 рабочих мест — один атомарный пакет. До 200 000 мест — задание с
  фиксированными пакетами, durable progress и остановкой неприменённой части.
  Конфликтный пакет не изменяется и не откатывает другие. Новые строки не входят
  задним числом. Шаги проверяют действующую личность/область/цель и версии заново.
- Большое задание продолжается подтверждённым клиентом из Портфеля. Закрытие
  окна/потеря связи приостанавливает продвижение; повторное открытие продолжает
  уже принятое сервером задание. Самостоятельного фонового scheduler пока нет.
  Это не офлайн-очередь будущих назначений: новое распределение без связи недоступно.
- Команда, версии, закрытие интервалов, отзыв соответствующих старых task grants,
  история и квитанция фиксируются под exclusive maintenance-barrier. Обычный
  писатель удерживает shared сторону до commit. Принятый раньше результат сохраняет
  автора; новая запись после передачи отвергается. Незатронутая работа сохраняется.
- `crm_assignment_changes` служит durable outbox инвалидаций. Изменения и квитанции
  защищены от UPDATE/DELETE/TRUNCATE; новые рабочие факты ими не создаются.

## Чтение, live и интерфейс

Эффективная модель используется в проверке доступа, рабочем портфеле, карточке,
реестре и текущих денежных срезах. Исходный текст назначения не выдаёт права и не
показывается как текущий ответственный поверх native head.

`changes` — авторизованные инвалидации без чужих ID/ФИО/результатов. Курсор содержит
позиции outbox/фактов и отпечаток области. Смена области, reconnect и перезапуск
перечитывают разрешённую модель. Snapshot устанавливается под коротким общим
барьером и затем удерживается PostgreSQL REPEATABLE READ без длительной блокировки
писателей; это устраняет пропуск ещё не зафиксированного меньшего sequence.

Транспорт первого кандидата — короткий polling в Electron main, 1 с, с ограниченным
backoff и проверенным IPC. SSE/push пока не реализованы. Токены не передаются в URL
или renderer. Последняя подтверждённая связь и изолированная среда обозначены.

Портфель группирует по `person_uuid`, раскрывает договоры/кредиторов/работы;
одноимённые внешние КД не склеиваются. Выбор клиентов/части КД/страницы/всего отбора
различается. Поиск цели показывает работы, команду, нагрузку и отсутствие аккаунта.
Выделение, раскрытия, ширины, масштаб и прокрутка защищённо сохраняются по личности.
Окончательное закрепление показывается после ACK. При неизвестном исходе защищён
исходный ID и доступна проверка квитанции. Открытый ввод не передаётся новой личности;
при утрате работы отправка блокируется, ввод/очередь сохраняются.

## Статистика и Команда

Текущие клиенты/КД/слоты, нераспределённые и нагрузка берутся из эффективной модели.
Долг и месячные реестровые суммы считаются по уникальным КД и отдельно по валютам;
неподтверждённые суммы/валюты имеют явное покрытие. Месячные суммы названы
«Поступления в текущем управляемом портфеле», исторический денежный автор не выдуман.
Звонки/выезды считаются по исходным авторам, независимо от текущего закрепления.

Ограничение первого среза фактов: текущий кадровый состав; неизвестный достоверный
день не включён. Полная временная кадровая область, scoped активное время команды,
единое раскрытие всех метрик до источника и новый экспорт ещё требуют завершения.

В Команде виден кадровый состав без договоров/аккаунта и переход к портфелю.
Входы/устройства запрашиваются через прежний manager gate с повторной проверкой
текущей личности. Подтверждение входа и временный пароль используют прежние серверные
политики; права/история не расширяются. Полная интеграция отзыва устройств/ролей,
всех административных действий и автоматического устойчивого сопоставления двух
источников ещё не закончена. По ФИО личности автоматически не объединяются.
Задачи доступны вторично из Команды, а также в клиенте.

## Старый контур: рабочее включение выключено

`distribution_mode` по умолчанию отсутствует: API возвращает явную причину
недоступности. Сейчас поддерживается только **isolated** для проверенного стенда.
Значение «production ready» намеренно не существует. Read-all не обходит этот gate.

Входящий legacy exchange сравнивает принятый baseline с native head: неизменённый
источник не возвращает старого исполнителя; совпавшее новое значение обновляет
baseline; divergent изменение остаётся конфликтом; неизвестное имя не снимает
ответственного. Initial authority import после native head запрещён.

**Не закрыт primary SQLite commit race и не сделана подтверждённая обратная проекция
назначений во все старые приложения/Excel.** PostgreSQL barrier сам по себе не
блокирует внешний SQLite endpoint. Распределение нельзя включать в смешанной рабочей
БД, нельзя обещать там обновление «везде» и нельзя выкладывать новые grants/worker
без отдельного проверенного пакета. В этом этапе рабочие сервер/данные/feeds не менялись.

## Поставка и воспроизведение

Внутренняя сборка: `HARD_CRM_MANAGER_INTERNAL=1 HARD_PRODUCT=crm node build.mjs`;
упаковка `HARD_CRM_MANAGER_INTERNAL=1 node tools/installers.mjs crm`.
Отдельные appId `ru.rimborso.crm.manager.internal`, профиль
`%LOCALAPPDATA%/Hard/crm-manager-internal/data` и каталог установки
`%LOCALAPPDATA%/Programs/hard-crm-manager-internal` сохраняют рабочий pilot.7.
Автообновления не публикуются. Подпись — существующий detached CRM Ed25519 manifest,
не Authenticode. Перед упаковкой нужен свежий frozen backend и payload audit.

Серверные проверки: `pytest tests/test_crm_assignments.py`; реальные PostgreSQL и
SELECT-only кадровые grants — `tests/test_crm_assignment_postgres.py` с изолированными
QA DSN. `tests/test_crm_manager_scale.py` проверяет 50 000+ синтетических КД.
Нативные сценарии: `test-crm-manager-distribution.cjs`, `test-crm-manager-live.cjs`
(4 отдельных профиля и один PostgreSQL backend), штатная двухзапусковая регрессия
`test-crm-employee-scope.cjs`. Приватный запуск, замеры, квитанции и утренняя инструкция
сохраняются в ROOT `_local/crm-manager-night-2026-11-14`; DSN/ключи в исходники не входят.
