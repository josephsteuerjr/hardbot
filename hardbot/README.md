# Бот выездного взыскания (hardbot) — v0.3

Внутренний контур КА: выездники работают карточки должников в Телеграме, аналитик
управляет всем из десктоп-пульта. Реестр (ЗК + Делимобиль) принадлежит КА, ролей нет —
только доверенные лица. Логика карточки — по образцу GoldenCrown. Подробный лор
проекта — в [AGENTS.md](AGENTS.md).

## Два процесса

| Кто | Чем пользуется |
|---|---|
| **Аналитик** | Пульт «Контур · Выезды» (`gui.py`, Tkinter): токен/ID/беседа, импорт/экспорт реестра, обзор сотрудников и привязок, запуск/остановка бота, **дев-режим** |
| **Выездник** | Телеграм-бот: при первом входе **сам выбирает себя** из реестра → свои клиенты → карточка → фиксация выезда. Язык ru/uz/tg |

**Самовыбор вместо раздачи id.** Выездник пишет боту `/start`, выбирает язык и
себя из списка «ответственных Сотрудников» (по загруженному реестру) — один раз,
фиксируется. Дальше клиенты подтягиваются автоматически по этому имени. **Беседа**
подхватывается сама: добавь бота в группу → владельцу прилетит «Принять?». **Договоры
одного человека объединяются** (карточка показывает все КД и суммарный долг; выезд
пишется во все).

ПД остаются на ПК аналитика — бот крутится локально, БД (`hardbot.db`) лежит рядом.

## Запуск (Windows, без Docker)

1. Поставьте Python 3.12+ («Add Python to PATH» при установке).
2. Скопируйте `.env.example` → `.env` (или впишите всё в пульте).
3. **Двойной клик `run.bat`** — поставит зависимости и откроет пульт.
4. В пульте: впишите `BOT_TOKEN` и `ADMIN_ID` → «Сохранить конфиг» → «▶ Запустить бота».

## Локализация (главное для выездника-СНГ)

Выездники СНГ часто плохо знают русский → интерфейс и **варианты ответов** переведены
на **русский / узбекский / таджикский**. Язык: кнопка «🌐 Язык» в боте или задаётся
аналитиком при добавлении доверенного лица. Значения статусов в БД хранятся каноничными
(русскими) — экспорт в реестр остаётся точным. Переводы правятся в `i18n.py`.

## Сохранность данных (обязательное условие)

- **SQLite в режиме WAL** — переживает аварийную перезагрузку, допускает одновременную
  работу бота и пульта с одним файлом.
- **Каждый шаг выезда пишется в БД сразу** — остановка поллинга/перезагрузка не теряет
  введённое.
- **`drop_pending_updates=False`** — сообщения за время простоя обрабатываются после
  перезапуска (Telegram хранит их до 24 ч).
- Импорт — **upsert**: повторная выгрузка обновляет сх-поля, не затирая назначения/визиты.
- Проверка целостности: `python selftest.py` (import→export→reimport побитово точен).

## Дев-режим

В пульте «🧪 Подготовить тестовую среду» — 30 синтетических клиентов закрепляются за вами
(`ADMIN_ID`), можно сразу тестировать UX как выездник.

## Пересылка в беседу

`/chatid` в беседе → впишите `GROUP_CHAT_ID`. После каждого выезда в беседу падает короткая
сводка (как сейчас руками).

## Рабочий цикл периода

1. Аналитик импортирует выгрузку (пульт → «Импорт xlsx»). В реестре есть колонка
   «ответственный Сотрудник».
2. Выездники в боте сами выбирают себя → клиенты подтягиваются по их имени.
3. Выездники отрабатывают через бота.
4. «Экспорт xlsx» → аналитик подтягивает данные обратно в мастер-реестр (.xlsb).
   Даты экспортируются типизированно (DD.MM.YYYY), суммы — текстом (ничего не теряется).

> VPS (Docker) оставлен под синтетику/демо, но контейнер бота остановлен — токен один,
> локальный запуск приоритетен. Для реальных ПД — только локальный пульт.
