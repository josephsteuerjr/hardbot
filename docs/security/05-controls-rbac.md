# 5. Контроль доступа и роли (RBAC)

Документ описывает модель доступа **в том виде, как она работает в коде** (модуль
`server/web.py`, `server/admin_access.py`, `server/ops_panel.py`, `server/db.py`).
Telegram — включаемый режим, а не основа входа: на закрытом контуре компании он
выключен (`BOT_TOKEN` пуст), и вход идёт по персональным ссылкам и токенам.

## 5.1. Кто есть кто

| Роль | Кто | Как опознаётся | Через что ходит |
|---|---|---|---|
| **Выездник / курьер** | полевой сотрудник | одобренная привязка (`agent_bind`, `approved=1`) | приложение (PWA), заголовок `X-App-Token` |
| **Руководитель** | старший направления/офиса | строка в таблице `managers` | приложение, `X-App-Token`; ручки `/api/manager/*` |
| **Владелец** | владелец системы | `uid == ADMIN_ID` (env) | приложение; в `/api/*` видит все дела |
| **Оператор (аналитик)** | пульт аналитика | устройство роли `operator` | `X-Device-Token` + `X-Device-Id`; `/admin/*` и `/ops/*` |
| **Инженер (ИТ)** | панель обслуживания | устройство роли `engineer` | `X-Device-Token` + `X-Device-Id`; только `/ops/*` |

Отдельной колонки «роль» у людей нет — роль вытекает из данных: одобренная
привязка делает выездником, строка в `managers` — руководителем, `ADMIN_ID` —
владельцем. Направление руководителя лежит в `managers.direction` (`tj`/`uz`/
`all`); его команда считается по `employees` + живому составу `office_cities`
(или по направлению целиком). `BIND_APPROVAL`/`is_trusted` в коде объявлены, но
**не вызываются** — на модель доступа не влияют.

## 5.2. Вход людей — персональная ссылка → токен приложения

- Ссылка вида `/i/<код>` (`_app_login`). Код одноразовой раздачи хранится в
  `app_links`; обмен `redeem_app_link` создаёт **токен приложения** и отдаёт его
  телефону во фрагменте адреса (`/#t=<токен>&fresh=1`). Телефон дальше шлёт токен
  заголовком `X-App-Token`; сам код в URL больше не участвует.
- **Окно ссылки** — 7 дней от выпуска (`APP_LINK_DAYS`). **Число входов** по
  ссылке: по умолчанию 2, оператор может задать 1..20 (`APP_LINK_MAX_USES`);
  первый вход с iPhone/iPad добавляет один разовый (перезаход из «Домой»).
- **Токен приложения** живёт 30 дней (`APP_TOKEN_DAYS`) и **скользит**: каждый
  успешный запрос продлевает срок ещё на 30 дней (`touch_app_token`), истёкший —
  отвергается. В базе лежит только его `sha256` (`app_tokens.token`), как у
  токенов устройств: копия базы входом не служит.
- **Выход с телефона** — кнопка «Выйти» в оболочке: `POST /api/logout` гасит
  ровно предъявленный токен (остальные входы человека живут), телефон стирает
  вход, портфель, карточки и кэши. Отказ сервера (401/403) стирает всё то же,
  кроме неотправленной очереди. Чужая ссылка входа при живом входе не
  подменяет его молча — оболочка спрашивает, показав, чей вход сейчас.
- Внутри Telegram (когда он включён) вместо токена приложение шлёт `X-Init-Data`,
  и сервер проверяет подпись Telegram (HMAC-SHA256 по `BOT_TOKEN`). При пустом
  `BOT_TOKEN` этот путь отключён полностью — остаётся только `X-App-Token`.

## 5.3. Что делает руководитель (`/api/manager/*`, гейт `_manager_gate`)

- Видит сводку, дела, карту, фотографии, статистику и план **только своей
  команды** (охват из `managers`).
- **Выдаёт и отзывает входы** своей команде: `POST /api/manager/app_link`,
  `POST /api/manager/app_revoke`; себе — тем же `app_link` с признаком «мне».
- Ведёт привязки команды: `POST /api/manager/binds` — `approve` / `reassign` /
  `unbind`.
- Тронуть вход владельца или другого руководителя нельзя: выдачу и отзыв ссылок
  закрывает `_foreign_privileged` (403), привязки — он же (404); одобрение
  чужой заявки не вытесняет устройство другого руководителя.

## 5.4. Устройства обслуживания — токен устройства

Пульт аналитика и панель инженера входят **не паролем, а токеном устройства**:

- Заголовки `X-Device-Token` (сам токен) и `X-Device-Id` (отпечаток машины,
  сверяется на каждом запросе). В базе (`admin_devices`) лежит **только
  `sha256` токена** (`token_hash`), не сам токен.
- **Две роли устройств:** `operator` (аналитик) и `engineer` (ИТ).
- Привязать устройство можно двумя путями:
  1. **мастер-ключом** — `POST /admin/device/enroll.json` с `X-Admin-Key`
     (гейт `_admin_master_key_only`); так заводится устройство роли `operator`;
  2. **одноразовым кодом** — код выдают на сервере (`admin_access.py issue
     --role operator|engineer`) или, только операторский, из пульта аналитика
     (`POST /ops/code.json` устройством роли `operator`; инженеру — 403: код
     пульта открывает должников). Пульт/панель обменивает код на токен через
     `POST /admin/device/redeem.json` (мастер-ключ не нужен). Код хранится как
     `sha256` (`code_hash`), одноразовый.

Что доступно роли устройства:

| Ручки | operator | engineer |
|---|:--:|:--:|
| `/admin/*` — данные должников, импорт/экспорт, настройки, привязки | ✅ | ❌ (401) |
| `/ops/*` — состояние, журнал, копия, восстановление, перезапуск, обновление | ✅ | ✅ |
| Выдать код **пульта** | ✅ (`/ops/code.json`) | ❌ (403) |
| Выдать код **инженера** | командой на сервере | командой на сервере |
| Отозвать устройство через `/ops` | только роли `operator` | только роли `engineer` |

Инженеру должники закрыты: любое `/admin/*` отвечает 401, а `/api/*` устройства
не пускает вовсе (там принимаются только токены людей).

## 5.5. Гейты и мастер-ключ

- `_admin` — пускает только устройство роли `operator`.
- `_engineer` — пускает `operator` **или** `engineer`.
- `_admin_master_key_only` — только `X-Admin-Key == ADMIN_API_KEY`.
- **Мастер-ключ `ADMIN_API_KEY`** после первой привязки устройства открывает
  ровно привязку/отзыв устройств: `/admin/device/enroll.json`,
  `/admin/device/revoke.json`, `/admin/key_check.json` и как запасной вход —
  список устройств. Данные должников им не открыть. **До** первой привязки
  (`admin_bootstrap_done()` = ложь) мастер-ключ временно открывает весь
  `/admin/*`: это разовый бутстрап, отметка о нём необратима. Отметка лежит и в
  базе, и **файлом** `admin_bootstrap.done` рядом с ней (`/data`): подмена базы
  (`migrate.sh receive --replace`, восстановление старой копии) ключу власть не
  возвращает.
- **Отзыв всех устройств роли** — `POST /admin/device/revoke.json`
  `{"all": true, "role": "operator"|"engineer"}`, только мастер-ключом: ответ на
  украденный токен оператора, который успел завести себе второе устройство.
- **Счётчик неудач входа:** 20 промахов за 300 с → 429 с `Retry-After: 60`.
  На `_admin` сверяется только на промахе: верный токен устройства не запирается
  (все пульты офиса выходят одним адресом). Считается по **первому** адресу в
  `X-Forwarded-For`, поэтому прокси обязан затирать клиентский заголовок (см.
  `deploy/README.md`, раздел про nginx).

## 5.6. Помощник на хосте (`hard-ops-agent`) — белые списки

Панель `/ops/*` живёт в контейнере и docker не видит намеренно (иначе пришлось бы
отдать `docker.sock` = root на всём сервере, включая чужие проекты). Заявку с
панели исполняет служба `hard-ops-agent` на хосте:

- **Закрытый список действий:** `doctor`, `logs`, `backup`, `restore`, `restart`,
  `update`; **единицы:** `core`, `stt`, `gps`. Ни строки из заявки не попадают в
  оболочку: действие выбирается из таблицы, параметры проверяются шаблоном.
- Идентификатор заявки проверяется шаблоном `^[A-Za-z0-9_-]{1,64}$` **до** любой
  работы; рабочие каталоги каждый круг сверяются, что они каталоги, а не ссылки;
  запись идёт через временный файл и атомарный перенос, не следуя за симлинком.
- Служба закрыта systemd-хардингом (`NoNewPrivileges`, `ProtectSystem=full`,
  `ProtectHome`, `PrivateTmp`, `Protect*`, `RestrictSUIDSGID`); каталоги `data` и
  `backups` — `chmod 700`.

## 5.7. Аудит

Таблица `audit(ts, actor, action, target, detail)`. Пишутся привязка/отзыв
устройств (`device_enroll`, `device_revoke`, `admin_bootstrap_closed`), выдача и
обмен кодов (`enroll_code_issued`, `enroll_code_redeemed`), заявки помощника
(`ops_request`, `ops_device_revoke`), вход по ссылке (`app_login`), выдача/отзыв
входов (`app_link_issued_admin`, `mgr_app_link`, `mgr_app_revoke`, `app_revoke`),
авторизация импорта. Чтения `/admin/*` в аудит не пишутся (пишется `last_seen`
устройства).

## 5.8. Прочие границы

- Токены и коды генерируются `secrets.token_urlsafe(N)`: код ссылки — 9,
  токен приложения — 24, токен устройства — 32, код привязки устройства — 24.
- Все `/api/*` проверяют «только свои» (`responsible == employee`); байпас — лишь
  у владельца (`ADMIN_ID`).
- `/admin/bot_token` (смена исходящего Telegram) доступен оператору; на контуре
  без Telegram он инертен.
- CORS для `/admin/*` разрешает заголовки `X-Admin-Key`, `Content-Type`; для
  прочих путей CORS включается только заданным `CORS_ALLOW_ORIGIN`.
- Каждый ответ несёт `X-Content-Type-Options: nosniff`, `Referrer-Policy:
  no-referrer` и запрет фреймов (`X-Frame-Options: DENY`, CSP `frame-ancestors
  'none'`; при включённом Telegram — только `frame-ancestors` с web.telegram.org).
- «Карта дня» (`/manager/map`) подписывается собственным секретом сервера
  (`MAPLINK_SECRET` или случайный в `settings`), не токеном бота; пустой секрет —
  отказ.
