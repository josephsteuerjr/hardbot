# Проверка входа и ролей — 06.10.2026

Проверен контур выдачи персональных ссылок, учётных записей без Telegram,
телефонных токенов, приложений сотрудников и руководителей на ПК, повторного
входа и отзыва. Desktop 2.0.2; оболочка PWA и контракт обмена не меняются.

## Исправленные причины

- Сотрудник получал служебный ID, занятый руководителем без строки `users`.
  Теперь ID выделяется в общей области всех таблиц входа под `BEGIN IMMEDIATE`;
  одновременные выдачи одному ФИО переиспользуют одну личность. Сервер отдаёт
  свободный ID для создания руководителя и отклоняет занятый служебный ID.
- Передаваемый клиентом класс iPhone увеличивал телефонную квоту; отдельный
  бонус ПК добавлялся к нему. Теперь максимум два телефонных обмена и одна
  отдельная активация программы на ПК. Неиспользованные телефонные входы
  не позволяют подключить второй ПК. iPhone и его ярлык занимают два
  телефонных хранилища. Старые действующие токены сохраняются.
- Полный отзыв не отключал `agent_devices`. Теперь он отзывает и телефон,
  и ПК сотрудника. Отзыв только ссылок сохраняет действующие устройства.
  Снятая/изменённая привязка тоже закрывает прежний ПК сотрудника.
- Токен ПК сотрудника мог наследовать руководящую роль аккаунта. Теперь этот
  класс токена открывает только собственный портфель: руководящие API его
  отвергают, bootstrap не выдаёт переключатель чужой команды.

## Проверенные границы

Сервер определяет личность по токену, роль — по своей БД, доступ к договорам —
по закреплению. Отказ другого класса входа не расходует ссылку. Одна программа
после успешного входа переходит в режим фактически принятого токена; первый
экран нейтральный. Сбой определения роли не открывает интерфейс другой роли.

Повтор с собственным действующим токеном не расходует активацию; чужой или
отозванный токен не даёт переиспользование. Истёкшая ссылка не активирует новый
вход. Истечение ссылки не отключает уже подключённое устройство. Перевыпуск
ссылки и полный отзыв — разные действия. Копирование является чтением и не
создаёт ссылку, токен или использование.

Руководитель видит и выдаёт вход своей команде; чужие руководящие ссылки
маскируются. СБ сохраняет границы чтения и охвата. Сырые токены не возвращаются
в renderer; локальные токены и очередь используют штатное защищённое хранилище.
При разборе вставленного текста принимается ровно одна ссылка; несколько
личных ссылок и URL с логином/паролем отклоняются. Проверка TLS сохраняется.

Проверки: 313 тестов в 23 изолированных модулях, без ошибок и пропусков;
Node-проверки очереди и ссылок; TypeScript; четыре сценария реального Electron
renderer на синтетических данных (Софт, Хард, ссылки команды, карточка
руководителя аналитика). Рабочие учётные записи не используются для имитации
звонков или расхода входов. Материалы рабочего инцидента хранятся в `_local/`.

## Практический предел

Персональная ссылка остаётся предъявляемым секретом: тот, кому её переслали,
может занять доступную активацию до истечения срока или отзыва. Ограничение
считает выданные входы, а не доказывает личность человека перед экраном и
не является аппаратной регистрацией физического ПК. Передавать ссылку нужно
лично; при ошибочной передаче использовать штатный отзыв. Проверка этого
контура не заменяет аудит всего продукта или независимый тест на проникновение.
