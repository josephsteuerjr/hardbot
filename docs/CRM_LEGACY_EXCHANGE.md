# Обмен со старыми приложениями

`crm.legacy_worker` работает отдельно от двух HTTP-приложений, через локальные файлы SQLite и сокет PostgreSQL. У него нет публичного входа. Конфигурация явно задаёт путь БД и список кадровых UUID для обратного обмена. Права и учётные записи не создаются и не расширяются.

Входящий срез читается в одной транзакции SQLite. Новые звонки и выезды сохраняют исходные номера строк, авторов, состав договоров, рабочие дни и сырые значения. Повтор строки не создаёт второе событие; изменение или исчезновение прежней истории создаёт вопрос для сверки. Неизвестные договоры и изменённые пары кредитор + КД автоматически не связываются.

Текущие поля сравниваются по трём значениям: последнее наблюдение старого приложения, общая карточка, новый срез. Одностороннее изменение применяется отдельным системным событием «Сверка прежнего приложения». Двусторонний конфликт сохраняется в `crm_migration_issues`; значение общей карточки остаётся прежним. Исходный baseline, первая копия строки и старые события не заменяются. Пересборка проекций воспроизводит системные события, которые не считаются работой сотрудника.

Обратное направление охватывает принятые звонки, выезды и их исправления только у явно указанной группы. Оно сохраняет точный охват договорами и автора команды. Запись старого журнала, поля, снимки для обогащения и квитанция SQLite фиксируются одной транзакцией. После сбоя подтверждения PostgreSQL повтор использует эту квитанцию. Собственные записи распознаются при следующем входящем срезе и не возвращаются вторым событием. Исправление меняет текущие поля без нового звонка или выезда в статистике.

Перезапись более свежего поля старого приложения запрещена. Спорная обратная доставка остаётся `needs_review` и не повторяется автоматически. Неприменённые события CRM также не отправляются. Отдельные обещания, контакты, заметки, задачи, доставки и документы остаются в общей CRM; они не превращаются в вымышленные звонки/выезды старого журнала. Обмен не изменяет личные Excel-книги и не является их выводом из эксплуатации.

Схема 3 добавляет только три таблицы: наблюдения источника, квитанции срезов и квитанции обратного обмена. Обновление выполняется миграционной ролью. Перед запуском обязательны точный preview, резервные копии и полная репетиция на отдельных копиях. Статус worker содержит время последнего среза, количества и ошибки без содержимого клиентских карточек.

Подготовка большого плана выполняется в согласованной транзакции только на чтение, без блокировки писателей CRM. Короткая фаза фиксации проверяет версии истории, журнал обслуживания, кадровые связи, назначения, идентичности и точные затрагиваемые строки. Если данные изменились во время подготовки, применяется новый просмотр; устаревший план не записывается.
