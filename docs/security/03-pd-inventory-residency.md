# 3. Классификация и инвентарь ПД + резидентность

## 3.1. Инвентарь персональных данных

Источник схемы — `server/fields.py` (50 колонок реестра) + служебные таблицы `db.py`.

| Объект (таблица) | Поля с ПД | Категория | Субъект |
|---|---|---|---|
| `clients` | ФИО (`client`), дата рождения (`birth_date`), телефон (`phone`,`phone_main`), адрес (`address`,`address_customer`), город, **долг** (разбивка по статьям), исходы выезда, координаты (`geo_lat/lon`) | **ПД + финансовые + спецконтекст (долг)** | Должник |
| `clients` (свободный текст) | `tips` (наводки: староста/соседи/ориентиры), комментарии | ПД третьих лиц (возможны) | Должник + 3-и лица |
| `visits` | история выездов (`payload`), `agent_id`=telegram_id выездника | Операционные + ПД сотрудника | Должник + выездник |
| `markers` | GPS-координаты, `telegram_id` | Геоданные + ПД сотрудника | Должник + выездник |
| `users` | `telegram_id`, язык | ПД сотрудника (идентификатор) | Выездник |
| `agent_bind` | `telegram_id` → сотрудник, `approved` | ПД сотрудника | Выездник |
| `audit` | `actor`(telegram_id), действие, `target`(договор) | Журнал доступа к ПД | Выездник + должник |
| Фото | `photos/<rep>/*.jpg` (адрес/двор/документы) | **Изображения — потенциально чувствительные** | Должник |

**Особо чувствительное** (минимизировать/ограничивать доступ): поле `client_location`
(«в РФ / на родине / СВО»), `purpose_rf` («СВО / лечение»), наводки `tips`, фото.

## 3.2. Классификация (уровни)

| Уровень | Данные | Правило |
|---|---|---|
| **C3 — Высокий** | ФИО+адрес+телефон+долг в связке; GPS; фото; наводки | Шифрование at-rest, RBAC, аудит, минимизация |
| C2 — Средний | telegram_id сотрудников, язык, история выездов | RBAC, аудит |
| C1 — Низкий | агрегаты/аналитика без идентификаторов, тайлы карты | Стандартные |
| C0 — Публичное | синтетика на демо-стенде | — |

## 3.3. Резидентность данных (ключ для локализации ПД)

| Данные | Где физически | Закрывает требование |
|---|---|---|
| Реальный реестр (`hardbot.db`) | **Он-прем**: ПК аналитика / мини-сервер в филиале РФ | 152-ФЗ ст.18(5), ZRU-547 ст.27-1 — первичная запись **в стране** |
| Бэкапы | **РФ** (Yandex Object Storage, S3) — план Фазы 4 | Хранение в РФ |
| Геокодинг адресов | Свой Nominatim/Photon или офлайн-газеттир (env) | Адрес не уходит в чужое облако |
| Демо/синтетика | VPS/демо-сервер | ПД нет → вне регулирования |
| Карта/тайлы | Свой PMTiles (Caddy) | Базовый слой не в чужом облаке |

**Вывод:** локализация ПД закрыта **архитектурой** (он-прем, данные не уезжают), а не
организационной мерой. Это сильнейший аргумент против Google/Yandex-облаков (см. §15 маппинг).

## 3.4. Минимизация и retention
- Минимизация: миниапп отдаёт выезднику только нужные поля; выездник видит **только своих**.
- Retention — см. [07-retention-ir-thirdparties.md](07-retention-ir-thirdparties.md)
  (230-ФЗ: записи взаимодействий — 1.5 года).
